# v2026.1001.0

> Released: 2026-10-01.

Three migrations (`0140`, `0141`, `0142`). One navigation for every company, agent visibility an administrator can narrow, a workforce hiring path with role templates, and a named-human control plane for operators working from a terminal.

## Added

- **Agent visibility** (#884 design, #885, #887, #888; migration `0142_agent_visibility`).
  - A company setting, **Settings › Members & access › Agent visibility**, with two choices. *Everyone sees every agent* is the default and changes nothing. *People see the agents they answer for* makes a member see the agents they steward or are accountable for, those agents' reporting lines, agents they created, and agents marked shared; they see those agents' work, their own work, and every issue in a project they are listed on. Administrators and instance admins always see everything.
  - A per-agent override on the agent page, **Visible to**: *Company default*, *Everyone*, or *Only the people who answer for it*. Admin-only.
  - A project access editor on the project page, **Who can see this project**: the open/restricted switch and a checklist of active humans. Listing someone shows them every issue in the project. This is the way to share work with a member in owner mode.
  - What a member cannot see is absent from every list and `404` on its id — agents, issues, approvals, activity, the dashboard, sidebar badges, org chart, heartbeat and live runs, and live-event delivery — the same rule restricted projects already enforce.
  - Agent actors are unaffected: an agent sees what it saw before.
  - Two short passages in the Onboard a steward and Agent kinds guides say what a newly paired person will see.
- **Workforce roles** (#882; migration `0140_workforce_enrollments`). Version-1 `marketing-content` and `sales-support` role templates, enrollment, company knowledge, and questions pinned to a named owner so a private answer is visible only to that person. Lives under **Settings › Agents › Workforce roles**, linked from Team and each agent's page. Questions waiting on you appear in Home's *Waiting on you* and on Decisions.
- **Named-human control plane** (#883; migration `0141_human_action_handles`). `/api/human-control` (`identity`, `discover`, `read`, `prepare`, `confirm`) for a verified named board key only. Handles are hashed, bound to user, key, target, operation and payload, expire after 15 minutes, and are claimed atomically before execution. `AGENTDASH_TOOLSET=human` exposes the matching MCP tools. Expired handles are swept hourly. Documented in `doc/HUMAN-CONTROL.md`.
- **Ross executive-OS scripts** (#878, #879). Operator CLIs under `scripts/ross/`, host-readiness scoring that refuses shared listener ports, a reporting contract, and an assistant request contract. `get_work_item` returns attributed Ross sources on issues that carry a Ross document; other customers' tasks make no extra reads. `whoami` now includes the company id.

## Changed

- **One shell for every company** (#874, #871, #872, #875, #876). The product profile no longer changes navigation or pages; MK capabilities are gated on the server only, and a page whose capability is off shows *Available on request*.
  - Sidebar: Home, Ask, Work, Decisions, Shipped, Team; a collapsed **More** group (Goals, Routines, Costs, Activity); a Help menu holding Guides; and one grouped **Settings** hub (Workspace, Agents, Data, …) that replaces the company and instance settings sidebars. Page URLs did not change.
  - **Inbox is now Decisions.** `/inbox`, `/inbox/{mine,recent,unread,all,company,new}`, `/approvals` and `/approvals/{pending,all}` redirect to `/decisions`, so bookmarks keep working. Decisions also lists steward asks, questions from your agent, connector writes with an unknown outcome, join requests, admin override items and **failed runs** (dismissable), and its badge counts everything it shows. Work gains *Touched by me* and *Unread* views.
  - Home is one Dashboard: the *Waiting on you*, *Working now* and *Shipped this week* blocks over the fleet, open-issue and spend panels. The Overview page is gone.
  - `GET /companies/:id/me/agent` and the assign route now answer `404` in a company without stewardship, before any agent or stewardship row is created. Creating an agent pairs its creator as steward only where stewardship is on.
  - A CI check (`check-no-profile-ux`) fails any new profile-driven UI.
- **Recovery budget clears only on Clear** (#877). Moving an issue out of `blocked`, commenting to reopen it, or reassigning it no longer clears an exhausted recovery budget; `POST /issues/:id/recovery-budget/clear` is the only clear. A run a person starts directly still goes ahead; automatic, linked, agent-, system- and assistant-started wakes are refused while the marker stands. PATCH and comment responses carry a `recoveryBudgetNotice` while it does.
- **Issue acceptance re-checks current authority** (#881). PATCH, comment and tree writes re-read the caller's credential, membership, grants, project access and every selected row under share locks, then re-check immediately before the write; field changes, comment, execution decision, references and audits commit in one transaction, and live events publish only after commit. An explicit but invalid `Bearer` or `x-agent-key` header is unauthenticated rather than falling back to the local operator. The restricted-project guard now covers agents too. Seven acceptance blocks are added to the default agent mandate.

## Upgrade notes

- **Three migrations: `0140_workforce_enrollments`, `0141_human_action_handles`, `0142_agent_visibility`.** All additive (two new tables, two new columns with defaults, check constraints). `ota-apply` needs `--allow-migrations`; rollback of this update restores the pre-update backup and discards data written after it.
- **Nothing is hidden until an administrator opts in.** Agent visibility ships with *Everyone sees every agent* selected for every company. After flipping it, mark shared agents *Everyone* and list members on the projects they need. A member's assistant and CLI narrow with the person: an agent key is unaffected, but a user-bound credential sees only what its user sees.
- People with Inbox bookmarks land on Decisions. The Advanced group is gone; Guides is behind the Help menu in the sidebar footer.
- Activity rows written by v2026.930.x may still carry the retired recovery-budget clear triggers; new rows use `explicit_action` only.
- OTA ordering from v2026.930.1 still applies: this release reports `releaseCommit`, so an updater at v2026.930.1 or later accepts it. An updater at v2026.930.0 or earlier applies it without that check.
- Follow-ups still open: #886 (members' configuration read on the agent page).
