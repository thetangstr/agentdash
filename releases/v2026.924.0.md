# v2026.924.0

> Released: 2026-09-24.

No migrations. Instance updates work end to end from the board again, the CoS
reviewer auto-hire goes through the hire approval, and `releases/` is now the
one connected release log.

## Fixed

- **An update can be offered.** The updater's new `--check` mode (#672, fixes
  #664) finds the newest applicable release tag, compares it with the installed
  commit (deployment state, then `git rev-parse HEAD`, then the legacy
  `source-state.json`), and writes `available-release.json` with an atomic
  write. Fetch failures and timeouts are recorded in the offer file instead of
  failing silently. Canary and `agentdash-connect-v*` tags are ignored.
- **"Update this instance" can be pressed.** The button used to wait for an
  approval, and pressing it was the only way to create one (#673, fixes #665).
  The server now reports `canApprove` separately from `canApply`, and an
  approval is bound to the exact commit on offer.
- **Deploy scripts run through `releases/current`.** Entry guards compare real
  paths, so running a script through a symlink no longer exits 0 while doing
  nothing (#671, fixes #666). Sixteen entry points across 15 files are fixed.
- **CoS reviewer auto-hire** (#683, fixes #669). It creates a runnable,
  `pending_approval` agent on the instance default adapter and files the normal
  `hire_agent` approval, instead of an unrunnable `process` agent that bypassed
  approval. Terminated reviewers no longer count as active. A per-company lock
  prevents duplicate hires. Terminating a reviewer unassigns its queue items.

## Changed

- **`AGENTDASH_UPDATE_APPLY=1` now refuses** and exits 2 with an explanation.
  Unattended apply is withdrawn until the `releases/current` launchd bootstrap
  exists (#687). Scheduled runs only check for updates and record them.
  Updates are applied from the board.
- **The reviewer queue sweep runs every 60 seconds.** Reviewers are told to
  review only issues assigned to them. Known gap: items left with no reviewer
  don't escalate yet (#701).
- **Release log.** `releases/README.md` indexes every release. The in-app
  Changelog sorts correctly, hides withdrawn cuts, and labels inherited
  Paperclip notes. CI fails a PR when a release tag has no notes (#689).
- CI rejects workflow files whose `run: |` blocks are broken (#561).

## Upgrade notes

- No migrations, and no new required environment variables.
- If an instance sets `AGENTDASH_UPDATE_APPLY=1`, its scheduled update job now
  exits 2 without applying. Unset it, or leave it set and apply from the board.
