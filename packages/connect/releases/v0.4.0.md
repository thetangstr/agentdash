# agentdash-connect v0.4.0

> Unreleased. Not yet published to npm.

## Behaviour Change

**Your agents' questions reach your own Claude, and you answer them there.**
When work reaches your agent — including work assigned to you — the agent
takes the first pass: it restates the request, works out a recommendation,
and asks you. Until now that question waited on the issue page. It now arrives
in your inbox:

- `inbox_sync` lists open questions from the agents you steward or answer for,
  after approvals and before blockers. Each carries the agent's name, the
  issue's identifier and title, the agent's restatement and options, and an
  `answer` handle.
- New tool `inbox_answer` sends your answer with that handle: `optionId` for a
  choice, `text` for a written answer or a note on a choice, `answers` for an
  ask with several questions. It is recorded as you, exactly as an answer on
  the issue page, and it wakes the agent.
- The inbox hook (`agentdash-connect inbox`) shows the same questions, quoted
  as the agent's words, and no longer reports "nothing waiting" while one is
  open.
- An approval in the digest now names the issue it is about.

The agent's text is framed as data, not instructions, in both places, and the
tools tell Claude to send only the answer you give.

Nothing is widened. An answer needs a handle minted for one question, for you,
on this machine; it expires after an hour and is spent once. The server
re-checks that the question is still pending and still addressed to you when
the handle is used, and the answer goes through the same validation as the web
page. A refused answer leaves the handle usable.

Needs an AgentDash instance that serves `/api/bridge/inbox/answer`. Against an
older instance, `inbox_answer` reports the server's refusal and nothing changes.

## Upgrade

Nothing to do. The inbox hook and the `agentdash-inbox` entry already run
`agentdash-connect@latest`; start a new Claude session once this version is
published.
