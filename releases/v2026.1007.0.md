# v2026.1007.0

> Released: 2026-10-07.

Run pages open on a new **Business** view: what the agent did, in owner words, and for runs that publish a milestone timeline, every step labelled Discover, Proposal, Negotiation, Agreement, Execution or Settlement. Your agents are visible in the left bar again, grouped by team. The rest is a pre-launch security pass: restricted projects, approvals, agent configuration, spend and plugin secrets now hold their boundaries on every route, malformed input gets a clean 4xx instead of a 500, and responses carry standard security headers. Hermes agents can run on an allowlisted SSH host, switched off unless an operator turns it on. No migrations. Everything merged since v2026.1005.0 (`b28cd800f`).

## Added

- **A Business view on every run** (#1059). Run pages open on Business by default; Readable and Raw are one click away, and your choice is remembered. A run whose issue carries a milestone timeline document (`ac.milestone-timeline/v1`, posted by the harness) shows each step with its milestone, what happened, whether the label was exact or inferred, simulated payments marked as such, refusals and errors, and the time; every line links to the raw log line it came from. A timeline must name the run it belongs to, and the page says who posted it. Runs without a timeline get a plain summary of what the agent did and how it ended (finished, did not finish, ran out of time, stopped). The live transcript now follows new output reliably and lets go as soon as you scroll up. See `doc/RUN-BUSINESS-VIEW.md` for the document contract.
- **Your agents in the left bar, grouped by team** (#1060). The agent list under Team is open by default. Agents are grouped under the agent they report to, each team collapses on its own, and the agent you are viewing is never hidden inside a collapsed team. Agents in a broken reporting loop no longer disappear from the list.
- **Hermes over SSH, off by default** (#1058). An operator can let a `hermes_local` agent run as a dedicated OS user over SSH, limited to an allowlist of targets per company with pinned host keys and a dedicated key. Only owners, admins and people who can create agents can pin an agent to such a host; agents never can. See Upgrade notes and `doc/HERMES-SSH-ENVIRONMENTS.md` before enabling it.

## Fixed

- **Restricted projects stay private everywhere** (#1037, #1039, #1055). Approval events and profile activity follow the project's access list; editing a restricted project you can't see answers "not found" instead of revealing it exists; and its workspaces, runtime services and GitHub connection no longer show to members who aren't on the list.
- **Approvals respect who can see the agent** (#1041, #1044, #1049). Deciding, resubmitting, commenting on or linking issues to an approval for an agent you can't see answers "not found", including through the assistant. Only an assistant grant can mark a hire as an assistant request. Creating an approval, linking its issues and logging it happen together or not at all, and nothing is announced before it is saved.
- **Agent permissions and configuration** (#1040, #1046). Only the board can change an agent's permissions, and an agent can't change another agent's skills through an edit. An agent's configuration, instructions and skills are readable by its steward or creator and by people who can create agents, not by every member; the create form's environment check works for everyone allowed to create agents.
- **Spend is shown to people who can read costs** (#1043). Members without cost access see "Visible to administrators only" on the dashboard instead of company spend.
- **Company boundaries on goals and plugin secrets** (#1038, #1042, #1048). A goal, its parent and its owner must belong to the same company, parent loops are refused, and deleting a goal that is still in use answers 409. A plugin can only resolve secrets for its own company.
- **Bad input gets a clean answer** (#1038, #1047). Malformed JSON, oversized bodies and unstorable characters answer 4xx instead of 500, and a very long issue reference or code block can no longer stall the server.
- **Security headers on every response** (#1051, #1061). Pages can't be framed by other sites (`X-Frame-Options` and CSP `frame-ancestors 'self'`), MIME sniffing is off, referrers are trimmed, HTTPS boxes send HSTS, and the server no longer advertises Express.
- **Cloud upgrades survive Railway's backup limit** (#1050). Before an upgrade snapshot, the control plane removes the oldest upgrade backups only when the volume is full, never scheduled or locked ones and never the newest two, and fails clearly without deleting anything when there isn't room. The billing status check is read-only again; promotion runs in the background (#1045).
- **Dependencies patched** (#1056): proxy-addr, the MCP SDK, sharp and source-map-js.

## Upgrade notes

- **No migrations.** Rolling back to v2026.1005.0 needs no database restore.
- **API changes for integrators.** Several routes now answer 404 instead of 403 or 200 for things the caller can't see (restricted projects, workspaces, approvals of invisible agents). Dashboard `costs` can be `null` for members without cost access (#1043). A foreign-key conflict on delete answers 409.
- **Hermes over SSH stays off** until you set `AGENTDASH_HERMES_SSH_ENABLED=true` and `AGENTDASH_HERMES_SSH_ALLOWLIST` (a JSON map of `user@host` to `{companies, identityFile, knownHostsFile, port}`). Read the residual-risk section of `doc/HERMES-SSH-ENVIRONMENTS.md` first: every agent running locally on the AgentDash host can read the dedicated key. SSH runs aren't metered, so budget hard-stops don't apply; set `timeoutSec` and `maxTurnsPerRun`. Known follow-ups: #1062 (the prompt is visible to other users on the target host; don't give a second company its own target user until it is fixed), #1063, #1064.
- **Milestone timelines.** Harnesses post them with `PUT /api/issues/{issueId}/documents/milestone-timeline-{runId}`; see `doc/RUN-BUSINESS-VIEW.md`. Fenced code blocks and whole-JSON bodies in any markdown field are now stored exactly as sent instead of having escaped line breaks rewritten.
