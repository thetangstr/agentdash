# v2026.930.0

> Released: 2026-09-30.

Two migrations: `0138` adds a partial unique index, and `0139` is a data-only fix. This release is mostly fixes:

- Stewards can connect their own terminal without company-wide admin rights.
- Terminating an agent frees its steward to take on another.
- A task whose automatic recovery ran out can be unblocked by a person.
- An overdue review item escalates once instead of every minute.
- Restricted projects stay restricted on every issue route.
- The OTA updater restarts, prunes and rebuilds safely.
- Optionally, one declared canonical address can be used for every link.

## Fixed

- **Stewards can connect their own agent** (#846, #847).
  - `POST /agents/:id/connect-codes` now accepts the agent's active steward. In MK-profile companies it also accepts the agent's creator while nobody else stewards it.
  - Before this, it required the company-wide `agents:create` grant.
  - Key management, pause and resume stay admin-only.
- **Terminating an agent ends its stewardship** (#847). The steward's one-agent slot is freed, so they can be assigned a new agent.
  - Only that agent's channel bindings are revoked. The person's bridge endpoints are untouched.
  - A terminated agent's stewardship can now be released, and My Agent no longer shows a terminated agent.
- **A stale hire approval can no longer terminate a working agent** (#847).
  - Approving an agent from its page now decides the linked hire approval too.
  - Rejecting a hire whose agent is already active returns 409, and the Override page warns and disables reject in that case.
- **Recovery budget** (#848).
  - A person can clear an exhausted recovery budget: by moving the issue out of blocked, reopening it by comment, reassigning it, or using the new "Clear recovery block & retry" action. Agent keys cannot clear it.
  - The budget now caps automatic retries only. The first run and cached input tokens no longer count, and while the budget is exhausted only runs a person started go through.
  - The stranded-issue reconciler no longer creates repeat recovery tasks for an exhausted issue. Its comments name the budget instead of blaming a lost wake.
  - Per-agent `runtimeConfig.recoveryBudget` overrides are board-only and bounded.
- **Review escalations fire once** (#849, #701, #833). This includes and supersedes #754.
  - An overdue review item escalates at most once per queue episode instead of on every 60-second cycle.
  - Items whose reviewer is terminated, paused or pending approval are swept back to the queue.
  - Auto-hire runs at most once per company per cycle and respects the normal queue-depth threshold.
- **Agent-requested sends** (#850).
  - `connector_send` approvals are validated when created. They must name a connector that can actually send, and a Teams-shaped request is refused with a pointer to the steward-inbox path.
  - The executor no longer falls back to HubSpot for an unnamed provider, and a HubSpot write gives up after 15 seconds.
  - An approved send that didn't deliver is reported to the requesting agent, the linked issues and the steward.
- **Restricted projects** (#854, part A of #830). Project access is now enforced:
  - on every `/issues/:id/*` route;
  - on the company activity feed, run lists and run details;
  - on approval links and execution workspaces;
  - on issue create and move.

  Ids that aren't a canonical UUID or an issue identifier return 404.
- **Edit-member dialog scrolls** (#845, #851). Lower grants and Save are reachable on short and narrow screens.
- **Issue references in markdown** (#851). A plain `WORD-123` token only links when its prefix is one of the viewer's companies' issue prefixes. Fragments inside UUIDs and model names no longer turn into issue links.
- **Run logs** (#851). A run that never started returns an empty log (`200`, `missing: true`) instead of a 404.
- **Bridge ids** (#855). A malformed `endpointId` or `taskId` returns 400 instead of a database 500.
- **Deliverable runs** (#855). Opening a run no longer relies on a caught unique violation, which removes repeated duplicate-key errors from the Postgres log.
- **Dependencies** (#856, #857).
  - `undici` is raised to at least 7.29.1 (GHSA-rfgv-xxqx-mfg5, GHSA-w293-vg96-wgc3).
  - `brace-expansion` is raised to at least 5.0.11 (GHSA-qhr7-859c-m2p7, GHSA-6j4f-fj2g-mc7p).

## Added

- **Declared origins** (#852, #547), opt-in.
  - `PAPERCLIP_CANONICAL_ORIGIN` and `PAPERCLIP_ORIGINS` declare the canonical address and every door people use. The old variables still work as aliases.
  - When set, the trusted origins are exactly the declared list, and approval, email, webhook and MCP links use the canonical address. Secure cookies are chosen per door.
  - Boot warns about a `.local`, private-IP or plaintext canonical address.
  - With neither variable set, behaviour is unchanged.

## OTA updater (#853, #833)

- **Default restart.** With no `--restart-command`, the apply restarts the server's launchd job. It first checks that every listener on the port belongs to that job, and refuses before anything is switched if it can't confirm that.
- **Rollback.** Rollback reads health before reporting its result.
- **Leftover release directories.** A completion marker lets a rerun reuse a finished release directory. An unfinished leftover is rebuilt, never the current or previous release.
- **Pruning.** It runs after a healthy apply and orders releases by version. It keeps the current and previous releases and anything in use. It skips entirely if the process list can't be read, and holds large batches until they are confirmed (`--prune --prune-confirm`). Untagged directories are pruned only with `--prune-untagged`.
- **Daily check.** A healthy apply installs its updater into `~/.agentdash/bin`, so the daily check runs the serving release's code.

## Upgrade notes

- **Migrations:**
  - `0138` adds a partial unique index on `issues (company_id, origin_kind, origin_id)` for `execos_request` origins. It fails only if duplicates already exist.
  - `0139` ends open stewardships whose agent is already terminated and writes one audit row per pairing it closes.
- **Stricter validation.** Bridge `taskClass` values other than `read` or `act` now get 400 instead of silently becoming `read`.
- **Recovery budget semantics.** While the budget is exhausted, non-retry automatic wakes are refused. Only runs a person started go through.
- **OTA on existing boxes.**
  - The first apply of this release still runs the previously installed updater, so pass `--restart-command` explicitly.
  - To preview pruning, run `--prune --dry-run` after the apply.
  - `install-launchdaemons.sh` refuses to install the update job until `~/.agentdash/bin` holds the new updater files.
- **Tests on production hosts.** The test suite now stops the services and SSH fixtures it starts, and fails a run that leaks them. Do not run it on a production host anyway.

## Known issues

- The first-run end-to-end test (`tests/e2e/first-run.spec.ts`) is intermittently failing in CI.
- Reviewerless escalations reach the Approvals and Override pages but notify no one.
- Project access is not yet applied to plugin routes, feedback traces, relation summaries, the verdict list or tree descendants.
