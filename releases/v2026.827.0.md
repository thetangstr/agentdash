# v2026.827.0

> Released: 2026-08-27

## Highlights

- **Invited members get resumable onboarding** — Each invited human now receives one company-scoped onboarding session that starts after invite acceptance, resumes after closing and reopening the app, and stays complete after finishing. Existing first-company bootstrap behavior is preserved. ([#530](https://github.com/thetangstr/agentdash/pull/530), @thetangstr)
- **Agent output persists through the supported run-attributed surface** — Worker guidance now includes the correct issue-comment endpoint, bearer identity, and run attribution header, while paired steward harnesses can reach their narrowly scoped directive and governance controls. ([#531](https://github.com/thetangstr/agentdash/pull/531), @thetangstr)
- **Automatic recovery has one aggregate task budget** — Recovery now fails closed across attempts, turns, tokens, cost, and elapsed time. Exhausted tasks remain available for explicit human remediation without silently triggering more provider calls. ([#531](https://github.com/thetangstr/agentdash/pull/531), @thetangstr)

## Improvements

- **One truthful open-work count** — Dashboard and setup-status surfaces now use the same open-task definition, including in-progress work exactly once. ([#530](https://github.com/thetangstr/agentdash/pull/530), @thetangstr)
- **Visible configured token cost** — When explicit input/output token prices are configured, recorded usage reports at least that calculated cost while preserving genuine subscription-included zero-cost receipts. ([#530](https://github.com/thetangstr/agentdash/pull/530), @thetangstr)
- **Bounded idle polling** — Due checks respect the configured heartbeat interval, coalesce against active runs, and retain the existing wakeworthy-work contract without recurring idle model calls. ([#530](https://github.com/thetangstr/agentdash/pull/530), @thetangstr)

## Fixes

- **Portable publishable sources** — Release scanning no longer finds a personal filesystem path or personal email in the affected documentation and fixture surfaces. ([#531](https://github.com/thetangstr/agentdash/pull/531), @thetangstr)
- **Stable recovery usage reporting** — Exhaustion reasons and aggregate usage remain truthful and human-remediable across automatic recovery attempts. ([#531](https://github.com/thetangstr/agentdash/pull/531), @thetangstr)

## Upgrade Guide

This is an in-place upgrade. Preserve the existing database, configuration, storage, and agent data; do not reinstall or reimport the instance.

One incremental migration, `0122_funny_valkyrie.sql`, adds a unique index on `(company_id, created_by_user_id)` in `onboarding_sessions`. Before upgrading, back up the database and run this read-only duplicate preflight:

```sql
SELECT company_id, created_by_user_id, COUNT(*)
FROM onboarding_sessions
GROUP BY company_id, created_by_user_id
HAVING COUNT(*) > 1;
```

Stop if the query returns any row. Otherwise, allow the normal startup migration path to apply only the pending migration. The migration does not delete or rewrite existing rows.

For metered providers, set and verify the deployment's intended input/output token pricing before accepting cost reporting. Do not copy synthetic staging prices into a customer environment.
