# v2026.927.0

> Released: 2026-09-27.

Three migrations, all additive. This release closes the loop the product
promises: a personal assistant can create and assign work over MCP, customers
connect their GitHub repo so agents can push and open pull requests, and the
app shows what was shipped. Hosted boxes gain a first-run flow, email-bound
claim links and support for the shared edge router. It is also the first
release that publishes a container image.

## Added

- **Assistant MCP work tools** (#745): `start_project`, `create_work_item`,
  `assign_work`, `comment_on_work` and `update_work_item`, available to grants
  with the `work` scope. Retries are safe: a repeated call returns the
  original item instead of creating a duplicate. Writes are limited to five
  exact routes and an allowlist of body fields, capped at 30 writes and 10 new
  issues per grant per hour, and every write is logged with the grant id.
- **Connect GitHub** (#802): paste a fine-grained token (one repository,
  Contents and Pull requests) and agents can push and open pull requests. The
  token is stored as a managed, encrypted company secret. Agents never see it
  in their environment. Git asks the server for it through a credential
  helper, which answers only for a live run of an agent assigned to that
  issue, for the project's connected repository on github.com. A GitHub App
  replaces the token before open signup (#797).
- **Shipped** (#798): a Shipped page listing every pull request and work
  product, with issue, agent, time and tokens. A Result block on issue detail
  shows its pull requests. Runs without usage show "not metered yet".
- **Home** (#801) for default-profile workspaces: what is waiting on you,
  what is working now, and what shipped this week. "Waiting on you" uses the
  same definition as the assistant's `list_pending_decisions`.
- **Hosted first run** (#804, #813): name the workspace, add the model key,
  connect GitHub, describe the first issue, land on Home. "Connect Muse" shows
  this box's MCP address and client id. The readiness assessment is optional
  (#803).
- **Hosted boxes:**
  - claim links bound to the claim email, single-use even under concurrent
    signups (#805, #814);
  - an edge gate that accepts only traffic from the shared router once
    `AGENTDASH_EDGE_SECRET` is set (#807);
  - company invites work while public signup is closed, with email binding
    enforced at acceptance (#743).
- **Release image** (#774): each stable release publishes
  `ghcr.io/thetangstr/agentdash:v2026.927.0` for amd64 and arm64, and records
  its digest in the GitHub Release. `/api/health` reports `releaseTag`
  (#752).

## Upgrade notes

- **Migrations:**
  - `0131` adds a partial unique index for assistant-created issues;
  - `0132` adds the GitHub repository connections table;
  - `0133` adds the single-row box claim table.
  All are additive.
- **Default-profile workspaces** get Home in place of the old overview, a
  Shipped item in the sidebar, and a readiness-assessment card in company
  settings. MK-profile workspaces are unchanged.
- **The first-run setup card** appears only on hosted boxes, for companies
  created from this release on or companies with no issues yet. Self-hosted
  installs and established companies see nothing new, and `/setup` stays
  reachable directly.
- **Secret names beginning `github-token-` are reserved.** Creating or
  renaming a secret to one returns 422. An existing secret with such a name
  is hidden from the list and ignored in agent, project and environment
  configuration, and an SSH environment that references one returns 422.
- **Run logs, run events and adapter results** are scrubbed of anything
  shaped like a GitHub token (`ghp_…`, `github_pat_…`) on every install.
- **Invites that carry an email** now require the signed-in account to have
  that email (case-insensitive) when accepting, including invites created
  before this release.
- **`PAPERCLIP_AUTH_DISABLE_SIGN_UP=true`** now admits signups that carry a
  valid company invite. Everyone else is still refused.
- **Health** reports `releaseTag` when `AGENTDASH_RELEASE_TAG` is set, and
  `claimed` on hosted, authenticated boxes.
- **Inert unless configured:**
  - the edge gate needs `AGENTDASH_EDGE_SECRET`;
  - the claim link needs `AGENTDASH_CLAIM_EMAIL`;
  - hosted-only behavior needs `AGENTDASH_DEPLOYMENT_KIND=hosted`.
  Existing installs set none of these.

## Known issues

- This is the first native arm64 build of the image. If the image jobs fail,
  the release itself stands. Recover with "Re-run failed jobs" on the release
  run (not a new dispatch), and hosted boxes can build from source until then.
- A unique database index on user email is tracked separately (#809), because
  existing installs may hold duplicate addresses.
