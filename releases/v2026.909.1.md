## Behaviour Change

**A run the platform lost is no longer reported as the agent's failure.** My
Agent showed `Process lost -- server may have restarted` under the heading
"What the adapter reported", in the colour reserved for a broken agent, beneath
a headline saying the agent had stopped and not run since. The adapter reported
nothing. `services/heartbeat.ts` describes its own behaviour exactly:
"`process_lost` is the reaper's inference, not an observation: it fires when
the server can no longer see the child, and after a restart that is a guess."
The same file notes that a detached process group routinely outlives a restart,
finishes the work, and reports back with a real result — so such a run may not
have failed at all.

Run health is now classified. `process_lost` reads as infrastructure: the
headline says the run was cut short when the server restarted, the recorded
text is labelled "What the platform recorded", and a line tells the steward
there is nothing here for them to fix, that the failure is an inference rather
than an observation, and that the agent will run again on its next trigger. It
renders muted rather than destructive.

Genuine adapter failures are unchanged — same red treatment, same "stopped and
has not run since", same "What the adapter reported" heading. A test pins that,
so this cannot quietly soften a real fault.

Expect fewer alarming panels immediately after any restart, including a
deploy. That is the point: a restart is something we did, not something the
agent did.
