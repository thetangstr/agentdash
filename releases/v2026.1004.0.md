# v2026.1004.0

> Released: 2026-10-04.

Stopping a run now stops it. A stopped run reads as stopped, not failed, and its agent stays healthy. The Chief of Staff (CoS) can hire after onboarding and counts its own chat honestly. Activity, Workforce, Costs and Settings read in plain words. Phones get a single back chevron, member cards and one way of showing hidden secrets. One migration (`0145`). Everything merged since v2026.1003.0 (`d0ae990cf`).

## Fixed

- **A stop sticks, and a stopped run is not a failure** (#1013). Marking an issue done no longer leaves its agent showing "error". A stopped run reads "Stopped", with the reason ("Stopped manually", "Cancelled because the issue was marked done"), in neutral styling. It has no red exit code, no "Run failed for an unknown reason" panel and no "run failed" event. After a manual stop, the agent isn't restarted on that issue until someone comments, assigns or resumes it. Stopped runs keep their token usage, exit code and logs.
- **The setup check says what's wrong** (#1013). A failed agent setup check shows the failing check and a hint, and agents that have run before see a softer "Re-check setup" state. Starting the agent is still blocked until the check passes. Re-checking no longer logs a console error.
- **The CoS agent page is honest** (#1019). It shows how many chat messages the CoS answered this month, instead of "has never run". Its ownership reads as "runs in your workspace", not as someone's own terminal. Error cards and notices aren't counted.
- **Run summaries skip warnings** (#1019). A stderr or warning line, such as a Hermes scanner notice, is never used as a run's summary. Normal summaries, checklists and multi-line notes are kept.
- **Signing in and joining** (#1017, #1021). /auth opens on Sign in once a workspace has people. An invited colleague lands on "You joined <workspace>", not on steward onboarding. Skipping the GitHub step in /setup takes you to the CoS, not to a first task that can't be created.
- **Shipped work stays current** (#1016, #1020). A deliverable's Result row updates when a new revision lands. "Counting…" ends right away for runs that report no usage.

## Changed

- **Hire after onboarding** (#1019). Ask the CoS for a new teammate at any time. It proposes the hire on a card, and only the person who asked can confirm it. If your workspace requires board approval for new agents, the hire waits for approval and the card says so.
- **Plain words** (#1015, #1014). Workforce, Activity, Costs, Settings, Health, Routines and the Team list use owner language. Specific changes:
  - Activity names system stops as AgentDash, with the reason.
  - Activity reads "accepted the product description" and "requested changes".
  - Costs says "Model usage" and "No budget limit set".
  - Developer-only notes (alpha adapters and plugins, the dev-server command) show only to instance admins.
- **Readable run stories** (#1016, #1020). The last raw-JSON tool results now read as short summaries ("Got company Acme Robotics") for Hermes, Claude and Codex. Internal file paths in summaries are shortened, and ordinary URLs are left alone. Health's token figure now matches Costs and the run page (input + output, cached reads listed separately). The agent page shows its tokens and spend from the same source as Costs.
- **Phones** (#1014, #1015, #1017):
  - A single "Up to <page>" chevron replaces the cramped breadcrumb trail.
  - Members show as cards.
  - The plan card lists every responsibility.
  - The connection badge shows a word only when something is wrong.
  - The sidebar workspace name ends with an ellipsis.
- **One review vocabulary** (#1014, #1018). Helpful / Needs work is hidden where Accept / Request changes already apply.
- **One way of showing hidden secrets** (#1014). Masked values read "•••• hidden" everywhere: run list, transcripts, comments and chat. Stored values are unchanged.
- **Hires are logged** (#1017). Agents hired from a plan or the CoS interview now appear in Activity.

## Upgrade notes

- **Migration `0145`** adds `author_agent_id` to chat messages, with an index. It's a nullable column, so the table is not rewritten. It also backfills older agent replies so the CoS page doesn't start at zero:
  - Replies in a steward conversation are credited to the agent that conversation is bound to.
  - Replies in the CoS thread and the Company Inbox are credited to the workspace's first Chief of Staff. Replies from a teammate summoned into the shared inbox before this release are counted as the CoS's. There's no better signal on those older rows.
  - Running it again changes nothing. Billing notices posted before this release may still count as chat answers.
- **Board approval applies to CoS hires.** In workspaces with "require board approval for new agents" on, a hire confirmed from a CoS card is created waiting for approval, with an approval request, instead of starting right away.
- **The health check reports `hasUsers` only on self-serve and hosted boxes** (#1017, #1021), where /auth uses it. Other instances report `false`.
