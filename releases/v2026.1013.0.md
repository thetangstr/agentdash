# v2026.1013.0

> Released: 2026-10-13.

A person's own Claude or Codex session can now work with their agent on the whole request loop. It can request work for a colleague with a read-back brief, review the agent's first pass with its own honest view, finish the work with the person and send it back as them in one confirmed bundle, and bring the result back to the requester. Agents hand work to each other directly, capped at three rounds per request, and every correction reaches the agent as a "what changed" summary. The new behaviour is off until an operator turns on `coworker_bridge_enabled` for a company. Inbox email pointers are now off by default.

## Breaking Changes

- **Inbox emails are opt-in per instance.** The pointer emails added in v2026.1010.0 run only when `AGENTDASH_INBOX_EMAIL=true` is set alongside `RESEND_API_KEY`. Without it no inbox email is sent, and the My Agent email switch is hidden. Transactional email (invites, password resets) is unaffected. ([#1096](https://github.com/thetangstr/agentdash/pull/1096), @thetangstr)
- **Agents hand work to other agents directly.** The default mandate no longer tells agents to ask their steward to relay a request; an agent assigns a child issue with a brief to the other agent. The receiving agent takes the same first pass and asks its own person unless its mandate lists that work. With `coworker_bridge_enabled`, at most three agent-to-agent hand-off rounds are allowed per request; the fourth is refused with `AGENT_HANDOFF_CAP_REACHED`. ([#1097](https://github.com/thetangstr/agentdash/pull/1097), @thetangstr)

## Highlights

- **Review and send back from your own session.** New bridge routes let the person's session list hand-offs, read the issue, comments, documents, attachments, extracted file text and the agent's run log, all scoped to what the person can see and framed as untrusted agent material. One propose and confirm handle sends an answer or decision, a document revision, a comment, lessons and files as the person, recorded "via bridge". ([#1097](https://github.com/thetangstr/agentdash/pull/1097), @thetangstr)
- **Request work for a colleague and get it back.** A person can request work for another person from their session; it routes to that person's agent. The requester sees their requests, who they are waiting on and for how long, reads the result, and accepts it or asks for changes, which go straight to the owning agent. ([#1097](https://github.com/thetangstr/agentdash/pull/1097), @thetangstr)
- **Agents learn from corrections.** A send-back, an answer that differs from the agent's recommendation, a requester's change request, a returned hand-off, a rejected approval or a reopened task reaches the agent's next run as a "what changed" summary. The default mandate tells agents to record lessons in their memory and to propose a mandate change, for the steward's approval, only when a lesson recurs. ([#1097](https://github.com/thetangstr/agentdash/pull/1097), @thetangstr)
- **agentdash-connect 0.5.0.** A review skill for Claude Code, Codex and Claude Desktop; Claude Desktop and Codex setup that merges into existing configuration with a backup; a `check` command; an opt-in `watch` that shows a desktop notification when something is waiting and can prepare a read-only review in advance. ([#1097](https://github.com/thetangstr/agentdash/pull/1097), @thetangstr)

## Improvements

- Agents can read the text of docx, pptx and text attachments, extracted on the server and framed. ([#1097](https://github.com/thetangstr/agentdash/pull/1097), @thetangstr)
- Files sent through the bridge travel only on restricted projects, are bound to the confirmed sha256, and are stored as `name vN (author).ext` with one current version per file. HTML, SVG, XML and macro-enabled Office files are refused on the bridge. ([#1097](https://github.com/thetangstr/agentdash/pull/1097), @thetangstr)
- The web app shows a "via bridge" badge on comments, revisions, answers and files sent from a person's session, and My Agent lists each connection's capabilities. ([#1097](https://github.com/thetangstr/agentdash/pull/1097), @thetangstr)

## Upgrade Guide

- Three migrations: `0149` gives every bridge connection that holds `bridge:inbox` the new `bridge:work` capability and writes one audit row per connection; `0150` adds agent corrections; `0151` adds attachment versions. All are additive.
- The new loop stays off until `coworker_bridge_enabled` is turned on for a company. Turn it on after setting up restricted projects for any work that carries confidential files.
- People reconnect with `npx agentdash-connect@0.5.0` to get the new tools and the review skill. The Chrome extension cannot use the bridge; use Claude Code, Codex or Claude Desktop.
- To keep inbox emails on an instance that wants them, set `AGENTDASH_INBOX_EMAIL=true`.
