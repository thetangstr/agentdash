# v2026.923.0

> Released: 2026-09-23.

No migrations. One feature: the steward onboarding procedure now lives in the
product, as pages that read this instance's own address.

## Added

- **Guides, in the app.** A **Guides** item in the sidebar opens `/guides`,
  with six pages bundled from `docs/guides`: for the steward — Getting started,
  Connect your terminal, Your inbox, Troubleshooting connect and inbox; for the
  admin — Onboard a steward (invite, agent, stewardship transfer, a six-row
  verification checklist, offboarding) and Agent kinds & stewardship. Rendered
  through `MarkdownBody`, mermaid included.
- **No address is ever hard-coded.** Guides carry the token `{{instanceUrl}}`;
  the page substitutes what this instance publishes (`publicBaseUrl` from
  `/api/health`), falling back to the browser origin — the same rule the
  connect command follows. The same files are listed in `docs/docs.json`, so
  the docs site and the app share one source.
- **Links where people are.** The connect card on My Agent links to the
  connect guide; the member-onboarding welcome step links to Getting started.
  Unprefixed links (`/guides/...`, the way a pasted URL arrives) redirect to
  the company-prefixed page.

## Changed

- `UnprefixedBoardRedirect` and `NoCompaniesStartPage` moved unchanged from
  `App.tsx` into `components/UnprefixedBoardRedirect.tsx`, so a route test can
  mount the real redirect beside the real pages.
- `guides` is registered as a board route root in `lib/company-routes.ts`, so
  the prefix helpers never read `/guides/...` as a company code. CI caught the
  omission; the existing `company-routes` test is what caught it.

## Tests

- `guides.test.ts` refuses any bundled guide that links to a slug that is not
  bundled, carries a token other than the instance address, or names a CLI
  that does not exist.
- `guides-routes.test.tsx` mounts the real router with App's route lines and
  visits every guide's exact URL, prefixed and unprefixed, asserting the
  landing path, the heading, and that the published address — not the
  browser's — is what appears. It also asserts App's route lines verbatim, so
  the tree it tests cannot drift from the app.
