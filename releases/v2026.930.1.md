# v2026.930.1

> Released: 2026-09-30.

No migrations. A patch release made of follow-ups from the post-merge review of v2026.930.0:

- Restricted projects no longer leak through live updates, related issues, blocker ids or feedback traces.
- The review queue can't stall a company, and each review round escalates.
- A creator whose stewardship was released can't mint connect codes, and assistant grants can't bypass an exhausted recovery budget.
- The OTA updater uses single-use approvals and checks that the new release is actually serving.

## Fixed

- **Live updates respect project access** (#864, part A of #830).
  - The live-events websocket filtered nothing by project. An off-list member or agent with the board open received restricted issue titles, comment snippets and run transcripts.
  - Each socket now gets only the events for projects it can see, using the same rule as the REST routes. An event that can't be resolved to a project is dropped for anyone who doesn't see everything, but only in companies with a restricted project.
  - A change to a project's access list applies from the next event.
- **Related issues, ancestors, blocker ids and feedback traces respect project access** (#868).
  - Blocker and blocked-by summaries drop issues the viewer can't see. Ancestor chains stop at the first ancestor they can't see.
  - `blockedByIssueIds` on create, child create and PATCH is checked like other body ids. A restricted, unknown or other-company blocker id now returns `404 Blocker issue not found` (was `422` for an unknown id). A PATCH by someone off the list keeps restricted blockers they can't see.
  - Feedback trace lists hide restricted traces, and single-trace reads return 404.
  - `GET /assistant/pending-decisions` blanks a restricted linked issue.
- **Review queue** (#867, follow-up to #849).
  - An item with no reviewer, whose only eligible owner is also its assignee, no longer throws on every cycle and stalls the whole company's queue. Each item is isolated, and the escalation skips the assignee.
  - When an issue comes back to review, its escalation window restarts, so a stalled second round escalates.
  - The escalation's verdict, approval, link and activity row are written in one transaction under a per-issue advisory lock, so two concurrent sweeps can't both escalate.
- **Stewardship and recovery** (#869, follow-up to #847 and #848).
  - A creator whose stewardship an admin released can no longer mint connect codes. A creator of a never-stewarded agent still can.
  - A run started by an assistant grant no longer counts as started by a person, so it can't bypass an exhausted recovery budget.
  - Unblocking an issue by PATCH clears the recovery marker in the same transaction as the status change, so the reconciler can't re-block it in between.
- **OTA updater** (#866, follow-up to #853).
  - An approval is single-use. After an apply that ends `applied` or `rolled_back`, `pending-approval.json` moves to `deployments/used-approvals/`. An optional `expiresAt` is honoured.
  - `/api/health` now reports `releaseCommit` when the server runs from a release directory. After a restart, the updater waits until health reports the target commit, and rolls back if it doesn't.
  - A rollback to an older release no longer downgrades the installed updater.
  - A release directory named by a launchd plist is never removed during a rebuild.
- **Dependencies** (#865). `axios` is raised to at least 1.20.0, which fixes five HIGH advisories, including GHSA-c29m-xwm3-cm6r.

## Also in v2026.930.0, missing from its notes

- **ExecOS request identity** (#844, migration `0138`). Issue create accepts `originKind: "execos_request"` plus `originId`. A second create with the same origin in the same company returns `409 EXECOS_REQUEST_ALREADY_RECORDED`, and the MCP `create_issue` tool passes both fields through. Agents and assistant grants can't write ExecOS-origin fields: the middleware answers 403 and the route 400.
- **Invalid ids return 400 on every route** (#855). Any uuid-cast error (Postgres 22P02) now returns `400 Invalid identifier` and is no longer logged as a server error, not only on the bridge routes.

## Upgrade notes

- No migrations. Rollback is a symlink swap.
- **OTA operators:** v2026.930.1 is the first release that reports `releaseCommit`. Applying it with a v2026.930.0 or older updater works. From then on, the updater only accepts a target that reports `releaseCommit`, so apply this release before any later one.
- An API client that relied on `422` for an unknown blocker id now gets `404`.
