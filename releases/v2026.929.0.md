# v2026.929.0

> Released: 2026-09-29.

Three migrations, all additive. Assigned work now starts when it is meant to:
`backlog` parks work and wakes nobody, `todo` starts it, and every path that
creates work now follows that rule. The default workspace profile gets the
1.0 navigation: six sidebar items, one Decisions page, a restructured agent
page and a Costs page that says what the money bought. Assistants can prepare
decisions and hires for a person to confirm.

## Fixed

- **Assigned work starts** (#834). Inbox `assign_work` created issues in
  `backlog`, which wakes nobody, so work assigned from a steward's terminal
  sat until someone commented. It now creates `todo`, wakes the agent, and
  takes an optional `description` brief. An instruction longer than a title
  becomes the brief instead of being refused.
- **Unowned `todo` gets an owner** (#834). An issue created as `todo` with no
  assignee goes to the company's Chief of Staff for triage. This only happens
  when the creator could have assigned it (`tasks:assign`), and never for an
  issue the Chief of Staff filed itself. Backlog stays unowned.

## Added

- **"Start new issues right away"** (#834), in Company Settings → Work, off by
  default. When on, an issue created without a status starts as `todo`
  instead of `backlog`. An explicit status always wins.
- **Agent instructions** state the rule (#834): create delegated work as `todo`
  when it should start now, and use `backlog` only to park it.
- **Assistant gated actions** (#780): `prepare_decision` and `request_hire`
  resolve and read back what they would do; nothing happens until the person
  confirms with a single-use handle. Needs the `agentdash:decide` scope. A
  grant can require a tap for every decision.
- **Sourced assistant reads** (#827): `whats_new` and `get_project` label each
  row with who set it — a person or the system, an agent, or the assistant.
- **Default profile, 1.0 navigation:**
  - six sidebar items — Home, Ask, Work, Decisions, Shipped, Team — with
    Advanced collapsed (#822);
  - one Decisions page in place of Inbox plus Approvals, with what approving
    and rejecting each will do (#817, #835);
  - agent detail reduced to Overview, Runs and Settings, with a vitals strip
    and a warning when most recent runs left nothing behind (#825);
  - Costs leads with spend, cost per shipped pull request and a by-issue
    breakdown; budgets, providers and billers move under Advanced (#826);
  - Settings → Connections for GitHub and the assistant (#823);
  - Settings → Model key, and a blocked state that names who can fix a
    missing key and lets them know (#824);
  - empty states that say what to do next (#820);
  - an Upgrade action on every plan-limit wall, and readable plan names
    (#818).
- **The AgentDash mark** replaces the leftover Paperclip icon in the tab,
  rail and app icons (#839).

## Upgrade notes

- **Migrations:**
  - `0135` adds the assistant action handles table and
    `assistant_grants.decisions_need_tap`;
  - `0136` adds `activity_log.origin`;
  - `0137` adds `companies.new_issues_start_as_todo` (default false).
  All are additive.
- **MK-profile workspaces keep their navigation.** Sidebar, Inbox, Approvals,
  agent tabs and Costs are unchanged there. They do get the fixes, the new
  Company Settings toggle and the new icon.
- **Issue create no longer defaults `status` in the shared schema.** The
  server resolves it: `backlog`, or `todo` when the company setting is on.
  Clients that relied on the schema default see the same result while the
  setting is off.
- **Board-created unassigned `todo` issues go to the Chief of Staff.** The New
  Issue dialog defaults to To do, so an issue a person creates without picking
  an assignee is now triaged by the CoS rather than left unowned.
- **Manual activity rows** are stamped with the server-side author and
  `origin: "manual"`; rows written before this release show their origin as
  unknown in assistant reads (#816).
- **The self-serve cloud control plane** (#836, #837) is a separate service
  under `cloud/`; instances are unaffected.

## Known issues

- Editing an issue into an unassigned `todo`, and issues created by plugins,
  are not yet routed to the Chief of Staff.
