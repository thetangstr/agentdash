## Behaviour Change

**A harness preflight that no longer describes its agent now says so.** Every
agent on the MK instance was showing evidence that had gone out of date: three
named `codex_local` while running `hermes_local`, and two reported "API keys
found: MiniMax" while running zai/glm and claimed no model was set when one
was. Read as a statement of what an agent runs, every one of them was wrong.

The evidence and the staleness detection were both fine. The logic existed
twice and the copies disagreed.
`evaluateAgentHarnessPreflightReadiness` compares the saved `configDigest`
against a hash of the current adapter configuration and refuses to start a run
on a mismatch — all five would fail that today. But the verdict was computed at
start time and discarded, and the panel reimplemented only the part it could
check without the configuration: present, well-formed, right contract version,
`status === "pass"`. The digest comparison is a server-side hash over data the
restricted view is never sent, so the panel fell through to "Harness preflight
passed".

`harnessReadiness` now travels with the agent record, from the same evaluation
that gates starting a run. It carries no configuration and no secret — only
whether the evidence still describes the agent, and why not. The stale state
still shows the adapter and date that were tested, so the mismatch is visible
rather than asserted.

**Expect agents to flip from "passed" to "out of date" on this release.** On
the MK instance that is five of them. It is the correct reading of their
current state, not a regression, and each is cleared by running preflight
again.

Agents whose evidence is genuinely current are unaffected.
