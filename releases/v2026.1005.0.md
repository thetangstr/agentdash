# v2026.1005.0

> Released: 2026-10-05.

Hermes agents can run on two model tiers — a stronger one for leadership roles, a lighter one for staff — on instances that opt in and have the Alibaba Token Plan (China) provider configured. The hire path reads end to end in owner words: who asked, what for, where it went, what the decision was. A comment on a finished issue stays a comment — it doesn't quietly reopen the work or wake the agent. One migration (`0146`). Everything merged since v2026.1004.0 (`05d8963ed`).

## Added

- **High and low model tiers for Hermes agents** (#1028, #1032). On instances that opt in (`AGENTDASH_HERMES_MODEL_TIERS=on`, see Upgrade notes), a new Hermes agent gets a strong model for leadership roles ("Qwen 3.8 Max · high tier") and a lighter one for everyone else ("DeepSeek V4.1 Flash · low tier"). CoS chat uses the high tier when no model is set. Cards, hire proposals and the agent page show the tier in plain words; a workspace on its own model key is never touched. Recorded tiers survive routine edits to an agent, and card text the server never stamped can't pass as a tier.

## Fixed

- **Hiring decisions read like decisions** (#1029). Decisions rows, the approval page and the CoS thread all say "Dana (via Chief of Staff) asks to hire Bea as Bookkeeper" — a name, a human title, never a role slug or an id. The card's buttons belong to the person who asked; everyone else sees "Waiting for Dana to confirm." Approval status reads "Waiting for a decision" / "Changes requested" / "Approved" / "Declined", raw ids and payloads sit under "Technical details", and a hired agent's page says who brought it on. Finance staff hired under titles like Bookkeeper or Payroll now get the neutral `finance` role instead of `cfo`.
- **A comment on a finished issue stays a comment** (#1031). Posting on a done or cancelled issue — yours or an agent's — no longer reopens it or wakes the agent, including @-mentions. Reopening is a deliberate act: tick "Reopen this issue" or hand the issue to a different agent. Stopped work is visible and resumable: the issue shows "Stopped by you — Resume", the run reads "Stopped" (not "cancelled"), your own stops toast as "Stopped by you", and raw plumbing lines no longer leak into run summaries and transcripts.
- **A failing setup check says what failed** (#1026). A saved failed verdict renders as a failure with its message instead of collapsing into a hidden state, and silently re-running it on every page view no longer logs errors under your name.
- **Activity and Health tell the truth** (#1026). Every system action gets a plain verb, pure plumbing is hidden by default, and Health counts your Accept / Request-changes decisions and real agent counts instead of only reviewer verdicts. The floating "Connected" badge no longer covers the last feed row.
- **The hire card keeps up with the hire** (#1025, #1027). A plan card waiting on a decision says so instead of "Team hired"; when the board answers, the card updates. Retrying a failed hire repairs what is missing without replaying welcome messages or rewinding a conversation that already finished, and posts its notice only when it actually repaired something. Only the person who asked for a plan can revise it.
- **Run summaries and chat replies keep real words, drop machine noise** (#1022, #1025, #1027, #1031). Runtime chatter written by an agent's own runtime — status lines, shell echoes, progress redraws — is stripped before a reply or summary reaches you, including lines that carry no warning glyph. An agent's own checklist ("✓ Fixed X") or a "ℹ Note:" opener is kept, on every adapter including Hermes.
- **Canary polish** (#1030). The Evaluation page no longer overflows on a phone; an agent's spend shows the same figure Costs uses, "Not measured" when usage was never recorded instead of a misleading $0.00; a masked secret can no longer turn into an email link; the invite page lands signed-in members in the workspace instead of hanging; after Accept or Request changes the Result chip and Decisions badge update without a reload.
- **Copy cleanup** (#1024, #1030). "Requested changes on … on ACM-1" grammar fixed, audit rows name the document they acted on, a long page title truncates on phones, stopped runs read "Stopped manually", and remaining "Paperclip" labels and engineering words read as AgentDash owner language.
- **The GitHub connect form keeps what you typed** (#1033). The project page no longer wipes the form while it settles, which also removes a CI flake.

## Upgrade notes

- **Migration `0146`** (with #1029) fixes where finance staff land. It replaces the `agentdash_backfill_agent_accountability` function so finance-staff titles map to the new neutral `finance` role instead of the executive `cfo` (only C-suite titles still map to `cfo`); `doctor repair-founder-owner` calls that function, so repaired rows get the corrected mapping too. It then remaps the rows earlier migrations already processed: agents sitting on `general` whose titles name finance work (bookkeeper, accountant, payroll, month-end close, …) move to `finance`. Every changed row writes an activity entry, titles/autonomy/accountability are untouched, and running it again changes nothing.
- **Model tiers are opt-in** (#1028). Nothing changes until you set `AGENTDASH_HERMES_MODEL_TIERS=on` on the instance. When on, every new `hermes_local` agent is assigned a tier model by role (leadership → high, everything else → low) and CoS chat rides the high tier when no model is set.
  - **Prerequisite:** the `alibaba-token-plan-cn` provider must exist in the Hermes config (`providers.<name>` in `~/.hermes/config.yaml`). It is not a built-in provider; without it the tier calls fail.
  - Shipped models: high = `alibaba-token-plan-cn` / `qwen3.8-max` ("Qwen 3.8 Max"), low = `alibaba-token-plan-cn` / `deepseek-v4.1-flash` ("DeepSeek V4.1 Flash").
  - Per-tier overrides: `AGENTDASH_HERMES_HIGH_MODEL` / `AGENTDASH_HERMES_HIGH_PROVIDER` and `AGENTDASH_HERMES_LOW_MODEL` / `AGENTDASH_HERMES_LOW_PROVIDER`. Always set the provider when you override the model — a model-only override still routes to `alibaba-token-plan-cn`, and an unpaired override is logged as a warning.
  - Tiers never apply to a workspace that configured its own model key through the setup flow, even with the switch on.
  - Existing agents are not moved automatically. `agentdash doctor apply-model-tiers` lists what each Hermes agent would move to; `agentdash doctor apply-model-tiers --apply` writes the tier (it never overwrites a model a person chose, and refuses to apply on a workspace-key box).
