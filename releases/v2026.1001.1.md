# v2026.1001.1

> Released: 2026-10-01.

No migrations. The agent-visibility read-back fix, plus everything merged between the v2026.1001.0 cut (`73a5b850a`) and this release's source (`2d8b576ee`): an exhausted recovery budget now holds until a named person lifts it, an assistant can ask Ross, the UI speaks people, and more restricted-project and review-queue fixes.

## Added

- **Ask Ross from an assistant** (#903, launch M2). `request_ross_assessment` (write, needs the grant's `agentdash:work` scope) and `ross_request_status` (read) MCP tools, backed by `POST /issues/:id/ross-requests` and `GET /issues/:id/ross-requests/:requestKey`. Only a named person can file; the request is one governed comment, coalesced by key under the issue lock; closed, cancelled and blocked tasks are refused rather than reopened; @-mentions are stripped so only Ross is notified; an exhausted task is refused. The response never claims a model run started.

## Changed

- **An exhausted recovery budget holds until a named person acts** (#877, #890, #904).
  - Moving an issue out of `blocked`, commenting to reopen it, reassigning it, @-mentioning an agent, or a manual wake no longer starts a run on an issue whose automatic-retry budget is exhausted. A person-started run that was queued when the budget ran out is cancelled.
  - A board user clears the block with **Clear recovery block & retry** (`POST /issues/:id/recovery-budget/clear`), which also resumes automatic retries. Clearing while a one-run authorization is pending cancels that run and records it.
  - Or a person authorizes **exactly one run** while the block stays: **Authorize one run** on the issue page (a review then confirm dialog), or `task_recovery.remediate` through `/api/human-control` with a named board key. That run can't continue on its own; the authorization expires after 15 minutes by default.
  - Who can authorize: company admins, holders of `agents:create`, and the agent's steward, accountable person or creator. Plain members and viewers see the block but get `403`, also through board keys.
  - Agents can no longer pick up an exhausted issue by checkout, by taking over its lock, or by moving it to `in_progress` from an unrelated run.
  - Permit *consumed* and *denied* activity rows are recorded by the system, naming the authorizer. PATCH and comment responses carry a `recoveryBudgetNotice` while the marker stands.
- **The UI speaks people** (#819). Every company, MKThink included: **Run Heartbeat** → **Wake now**; *Heartbeat on interval* → **Run on a schedule**; **Run preflight** → **Check setup** (messages say "setup check"); instance **Heartbeats** → **Schedules** ("Agent Schedules"); **Company Settings** → **Workspace settings**; *Require board approval for new hires* → **Require your approval**; "paused by board" → "paused by a person"; "in v1" is gone from sign-up. URLs are unchanged.
- **Restricted projects stay restricted in more places** (#842, #905, #906). `/costs/by-project` and `/costs/finance-events` drop restricted projects for people off the list. A hidden parent reads as no parent, hidden blockers are not named in blocker samples, and hidden issues are removed from `issue.blockers_updated` and referenced-issue activity on REST and live events. `issue.deleted` reaches ordinary members again. Company reads return `agentVisibilityDefault`, so the Settings choice shows what was saved.
- **Review rounds** (#905). A `failed` verdict from an earlier round no longer drops a revised issue from the review queue; escalation activity publishes after commit.

## Fixed

- **The Agent visibility setting now reads back.** Company reads went through an explicit column list that did not include `agentVisibilityDefault`, so `GET /companies/:id` and the `PATCH` response never carried it. The server enforced the saved value (the rule reads the column directly), but the radio under Settings › Members & access always showed *Everyone sees every agent*, whatever an administrator had saved. The column is in the list, and the route test now asserts the value on both the read and the write response.

- Declared origins log a boot warning that enabling `PAPERCLIP_ORIGINS` signs TLS-door users out once, and that SSO started on a door whose scheme differs from the canonical origin fails (#900).
- Issue references with an all-hex company prefix (ABC, CAF, FAB, BED, DEF) link again (#900).
- A `400 Invalid identifier` is logged at warn with the route and parameter names (#900).
- `connector_send`: a database error before the claim row is written reports "failed, nothing delivered" (#900).
- The model-key nudge cooldown is atomic, and `/billing/status` answers `404` for an unknown company (#843).
- The repo no longer publishes real tailnet or LAN addresses (#895).

## Upgrade notes

- No migrations. Rollback is a symlink swap.
- **Recovery behaviour changed from v2026.930.x and v2026.1001.0:** unblocking, reopening by comment, reassigning or @-mentioning no longer restarts an exhausted issue — only **Clear recovery block & retry** or a named person's **Authorize one run**. The v2026.930.0 notes said otherwise.
- **Wording changed for every company, MKThink included** (Wake now, Schedules, Workspace settings, your approval).
- **Images:** `ghcr.io/thetangstr/agentdash:latest` and `sha-*` publish again from `main` (#892); release verify jobs now allow 60 minutes (#893).
- Follow-ups still open: #886, #891's lows, #902 (budgets overview leaks restricted project names), #907 (on-volume backups omit CHECK constraints, views, functions and triggers).
- If an administrator already switched a company to *People see the agents they answer for* on v2026.1001.0, that setting was in effect the whole time; it simply did not display.
