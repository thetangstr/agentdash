One squash past v2026.915.0, and **it carries a migration** —
`0128_steward_webhooks`, one new table, nothing existing touched. Additive,
but Drizzle has no down-migrations: rolling back past this release means

release unless run with `--allow-migrations`; take the backup first and read
this paragraph before overriding.

## Behaviour Change

**The inbox can now push, to a webhook, without a bot.** Two stewards
independently built pollers because nothing pushed; one then asked to grant an
agent Board access so channel text could decide approvals. This feature is the
sanctioned shape of the first need and the standing refusal of the second.

A steward pastes a Teams Workflows webhook URL on their My Agent page
("Get told in Teams"). Registration challenge-posts to the URL and refuses one
that does not answer. From then on, a once-a-minute sweep watches that
person's durable inbox log and, when it advances, POSTs the same ask-and-
pointer digest the inbox renders — owner-named, deep-linked to the approvals
page. Delivery keeps a cursor per webhook over the same gap-free sequence
machine endpoints use: a failed POST retries the same window; a delivered one
advances; a revoked webhook goes silent immediately.

Three properties are pinned by tests against the actual wire bytes:

- **Never the evidence.** The approval payload does not appear in any
  delivered message.
- **Never a decision handle.** The digest is built handle-less for webhooks —
  the first implementation minted callback tokens and the foreign key refused
  it; zero such rows is now the specification.
- **The steward's own.** Registration, listing and revocation exist only under
  `me/`; the URL never returns whole (host hint only); every registration and
  revocation is audited.

Deciding stays on the page. A Workflows webhook has no verifiable sender, so
nothing arriving from the channel can decide anything — the message links to
where deciding happens. The dormant bot-based card path remains the future
in-Teams decision story, when a customer provisions a bot registration.

## Operational notes

The sweep runs unconditionally (the webhooks table is the on/off switch —
zero registrations, one cheap query a minute). The audience of the chosen
channel is the steward's own call and the page says so: everyone in the
channel sees the summaries.
