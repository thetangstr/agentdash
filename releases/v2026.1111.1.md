# v2026.1111.1

> Released: 2026-11-11.

Claude Code can now connect to AgentDash as a person's own assistant. Settings save only when you press **Save changes**. The public site has a new "How it works" page. No migrations.

## What's new

- **Claude Code can connect.** Claude Code signs in to the assistant connection (`/api/mcp/assistant`) with a client metadata document whose return addresses are on the person's own machine (`http://localhost/callback`, `http://127.0.0.1/callback`). AgentDash refused that document before the consent screen ever showed, so Claude Code could not connect at all, and batch changes from an admin's own Claude were out of reach for Claude Code users. Those loopback return addresses are now accepted.
- **Settings save on an explicit "Save changes".** Switches, selects and fields in Company settings (General and Appearance, Hiring, Work, Admin powers, Agent access rules) and Instance settings (General, Experimental) change a draft. **Save changes** sends only the fields you changed, in one request. **Discard** puts the saved values back, and one line says "Unsaved changes", "Saved" or the error. A refused save keeps your draft so you can try again. Saving **Enforce** for agent access rules still asks for confirmation first. Turning on auto-recovery still shows its preview, and **Run now** always uses the saved settings, never the draft.
- **"How it works" on the public site.** A new page at `/how-it-works` walks through how AgentDash works, as an animated illustration with a text version for screen readers and reduced motion. The 3D library loads only on that page. "How it works" in the site header and footer now opens it.

## For admins

- Switches you used to flip with instant effect now wait for **Save changes**. Leaving a page with unsaved changes gives no warning yet.
- Lists with their own per-item buttons (labels, ceiling templates, invites, members, logo and avatar) still act on each button, as before.
- To connect Claude Code, add the instance's assistant MCP server in Claude Code and sign in. The consent screen is unchanged: batch changes still need the company switch on, the person to be an owner or admin, and the box ticked on the consent screen.

## Upgrade

- No migrations. Upgrading from v2026.1110.1 or earlier also runs the migrations of the releases in between: `0162` from v2026.1111.0 and, from v2026.1109.1 or earlier, `0158` to `0161` from v2026.1110.0. Their notes describe each one.
- The launchd installer (`docker/launchd/install.sh`) now disables a legacy `com.paperclip.server` service whose wrapper script is gone, after the new service is built and before it is installed. It moves that plist aside to `com.paperclip.server.plist.migrated.bak.<timestamp>` rather than deleting it, and leaves a legacy service that still works, or that points at something else, alone.
- Rolling back to v2026.1111.0 brings back instant-save settings and Claude Code's refused sign-in. Nothing stored changes.

## Security

- A client metadata document may name a loopback return address on any origin. The authorization code then goes only to the person's own machine. PKCE (S256) is still required, the requested return address must still match one the client registered (only the port may differ for loopback, as before), and the code is still bound to the exact address used. Every non-loopback return address must still share the document's origin.

## Breaking Changes

- None for the published contract. Settings controls that saved on each click now save on **Save changes**; scripts that drive the UI must press it.
