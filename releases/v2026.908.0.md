# v2026.908.0

> Released: 2026-09-08 as v2026.908.0.

Twenty-three squashes past v2026.904.0. One migration, forward-only. The bulk
of it is the Company Evaluator, milestones 0 through 5, which lands in shadow
mode and changes nothing a steward sees. The rest is the steward-facing surface
on AgentDash-MK: the My Agent page, two production incidents fixed at their
root, and three dependency floors raised past high-severity advisories.

## Behaviour Changes You Must Read First

**This release carries one migration and there is no way back by code alone.**
`0127_company_evaluator_ledger` creates three tables — `evaluation_events`,
`evaluation_ingest_state`, `evaluation_scorecards` — and adds one nullable
column, `principal_kind`, to `agent_api_keys`. It is additive: nothing existing
is dropped, narrowed, or backfilled. But Drizzle has no down-migrations, so
rolling this release back means restoring the backup taken before it and losing
whatever was written since. The OTA updater refuses a migrating release unless
run with `--allow-migrations`. That refusal is correct; read this paragraph
before overriding it.

**My Agent has one way to connect, and it is not the one the page used to show
first.** The page previously offered two: a visible card that walked a steward
through writing a bridge token to a file and installing a `SessionStart` hook,
and a fold at the bottom, labelled for whoever operates the machine, holding
the connect-code flow. The visible one could not work. `stewardInboxService`
refuses `/api/bridge/inbox/*` for any endpoint without the `bridge:inbox`
capability, and the enrolment call requested `bridge:read` alone, so every key
the UI has ever minted got 403 from the hook it had just installed. In
production all seven enrolled endpoints are in that state and
`steward_inbox_events` has never been read by anything.

The connect-code flow is now the only one on the page: a button, an
eight-character code good for ten minutes and one use, and a single
`npx agentdash-connect` line. `ConnectInClaudeOrCodex`, `ConnectYourHarness`
and `ConnectYourMachine` are deleted.

**Enrolments from now on request `bridge:inbox`; existing endpoints do not have
it.** Anyone already running `~/agentdash-inbox` keeps their files, and their
hook keeps failing, until they enrol again. Endpoints already issued were
deliberately not backfilled: widening a credential somebody already holds
should be a decision, not a side effect of an upgrade.

**A stopped agent now says why, on its own page.** `GET /me/agent` returns
`status: "error"` and no cause, so My Agent showed the word and nothing else
while its headline — which counted assigned issues and never looked at run
health — read that the agent was working on three things. Worse, the newest run
is usually the uninformative one: when automatic recovery gives up it writes its
own cancelled entry on top, carrying `task_recovery_budget_exhausted` and
nothing about the fault. A steward diagnosing his own agent reported nearly
filing the wrong root cause off that display. The page now reads past the
recovery marker to the failure underneath, names the marker so nobody has to
know it exists, and stops at a success so an already-fixed fault is never shown
as current.

**Automatic recovery may no longer change an agent's adapter or model.** It
could, and it did: HAL was moved off `hermes_local` onto `claude_api` with its
model dropped, which produced "Process adapter missing command" and looked like
a configuration error somebody had made by hand. Recovery now refuses and
retries instead of reconfiguring.

**Hermes agent-home runs no longer crash on an undefined working directory.**
A guard in our own adapter patch read `.length` off a value that is `undefined`
whenever no `cwd` is configured, so every agent-home run failed. Every test
passed because the harness set a `cwd` on every context it built.

## Company Evaluator, Milestones 0 to 5

Shadow mode. It reads, scores and reports; it decides nothing and no steward
surface changes. Milestone 1 added the append-only ledger, ingest and replay.
Milestone 2 added the deterministic scoring engine and treats exceptions as
findings rather than swallowing them. Milestone 3 added a read-only evaluator
principal with locked provisioning and a shadow cadence. Milestone 4 added the
dashboard, drill-down and founder view. Milestone 5 added shadow-run records, a
graduation report and a runbook, and calibrated rule P6 so it judges only
evidenced transitions.

## Also In This Release

- Authority refusals are recorded as `authz.refused` activity events, so a
  refusal is now visible rather than silent.
- The public website is rebuilt around the stewarded Chief of Staff, with a
  Remotion story and a simulated demo.
- Four empty states stopped reporting a failed load as an empty one. A query
  error read as zero results, so a page whose request had 500'd said there was
  nothing waiting.
- A waiting chip that read "waiting 2d ago" now reads as a duration.
- The inbox check is scheduled in the operator's own harness rather than by
  anything here, and it no longer acknowledges approvals it never displayed.
- `dod_set` activity records the real actor and the previous definition of done.
- Roles render as job titles: "CEO", not "ceo" or "Ceo"; "Chief of Staff", not
  "Chief Of Staff".
