# agentdash-connect v0.2.0

> Released: 2026-09-14

## Highlights

- Redeeming a connect code now sets up the inbox half of the connection, when
  the instance provides it: the bridge endpoint token is stored at
  `~/.agentdash/bridge-token` (mode 600) and a dedicated `~/agentdash-inbox`
  workspace is scaffolded whose `SessionStart` hook surfaces what is waiting —
  approvals first, then blocked agents, then finished work.
- New `agentdash-connect inbox` subcommand: reads the steward inbox with the
  same rendering, ordering and accounting as `paperclipai bridge inbox`, and
  the same rule that it never exits 2 — an unreachable inbox must not be able
  to stop a session from starting. This is what the scaffolded hook runs, via
  `npx -y agentdash-connect@latest inbox`, so the machine needs nothing but
  node and npx.
- The instance address for `inbox` is recovered from the MCP configuration the
  connect flow wrote, so the hook needs no flags beyond `--server` when one is
  baked in at scaffold time.

## Compatibility

- Against an instance older than v2026.914.0, redeem returns no `bridgeToken`
  and the inbox setup is skipped cleanly; pairing behaves exactly as 0.1.5.
- Older CLI versions ignore the new response fields. The pairing they perform
  still works; only the inbox half is missing until the CLI is updated.
