# v2026.1031.0

> Released: 2026-10-31.

Agents become the evaluated subject. Each agent has a versioned operating profile, written by a person and applied only after approval. Access rules (what an agent can see, do and talk to) are enforced by the server, where a company turns them on. Each agent gets a scorecard drawn from real records. This release also patches high and critical dependency advisories, including the login library, and moves validation to zod 4.

## Breaking Changes

- **Agents can no longer edit `capabilities` on themselves or on peers.** `PATCH /api/agents/:id` from an agent answers `422 AGENT_FIELD_PROFILE_MANAGED`. The text now comes from the agent's operating profile. Board users with configuration authority can still edit it. ([#1107](https://github.com/thetangstr/agentdash/pull/1107), @thetangstr)
- **The default activity feed hides two system actions,** `access.would_refuse` and `agent_profile.application_step`. They stay in the record. Pass `includeSystem=true`, or use "Show system events" on the Activity page, to see them. ([#1107](https://github.com/thetangstr/agentdash/pull/1107), @thetangstr)
- **Stricter validation from zod 4:**
  - date-times must include seconds (RFC 3339, as documented);
  - integers beyond 2^53 are rejected;
  - URLs are trimmed.

  zod's own default error wording changed, for example "Invalid input: expected string, received undefined" instead of "Required". The response shape `{ error: "Validation error", details }` and all messages AgentDash writes are unchanged. ([#1109](https://github.com/thetangstr/agentdash/pull/1109), @thetangstr)
- **Project and goal scorecards get a new formula version, `m2-score/9`.** A checkout now counts as an assignment plus a transition, and agent-side events are no longer milestone inputs. The next snapshot stores a new card version. ([#1107](https://github.com/thetangstr/agentdash/pull/1107), @thetangstr)

## Security

- **Login library:** better-auth 1.6.23 → 1.7.14, fixing a critical advisory (GHSA-965c-763c-88jm) and two high ones. Existing Microsoft sign-ins are kept by migration `0153` (see the Upgrade Guide). ([#1108](https://github.com/thetangstr/agentdash/pull/1108), @thetangstr)
- **Other dependencies with high advisories,** upgraded to patched versions: undici, multer, body-parser, dompurify, follow-redirects, vite and @azure/msal-node. ([#1108](https://github.com/thetangstr/agentdash/pull/1108), @thetangstr)
- **zod 3 → 4,** fixing GHSA-mrhx-c7xc-m3w5 (memory exhaustion on large invalid arrays). No dependency advisory is allowlisted any more. ([#1109](https://github.com/thetangstr/agentdash/pull/1109), @thetangstr)

## Features

- **Profile, Access and Performance tabs on every agent.**
  - The Access tab shows what the agent can see, do and talk to, each item with five states: requested, defined, enforced, working and used. It also states the execution environment, and that a local agent's host is not restricted.
  - Profile shows a starting profile derived from today's records until a person writes one.
  - Performance answers six questions: owed work, quality, acceptance and use, cost, boundaries, and what needs a decision. Unknown is shown as unknown. ([#1107](https://github.com/thetangstr/agentdash/pull/1107), @thetangstr)
- **Operating profiles, approved before they apply.**
  - A person drafts and proposes a profile; the `agent_profile_change` approval needs exactly the authority that a direct edit of each changed field needs.
  - Application is one agent at a time, refuses stale changes, records every step, and can be resumed.
  - The agent's contract is declared to the evaluator, work can be mapped to responsibilities, and the profile reaches the agent's instructions with delivery recorded at run start. ([#1107](https://github.com/thetangstr/agentdash/pull/1107), @thetangstr)
- **Access rules per agent: off, shadow, then enforce,** chosen per company by an admin. The default is off.
  - In shadow, would-be refusals are logged and nothing is refused.
  - In enforce, out-of-scope actions get `403 ACCESS_POLICY_REFUSED` with the reason and how to ask for more. A run outside the agent's projects doesn't start, and a mention outside its contacts keeps the comment but wakes no one.
  - The accountable person, the steward and admins are always reachable. ([#1107](https://github.com/thetangstr/agentdash/pull/1107), @thetangstr)
- **Agent scorecards.**
  - Owed work is generated from schedule history, so days when nothing ran still count.
  - Projects led and goals owned roll up separately from work delivered.
  - Automated acceptance, human acceptance, use and outcome stay separate facts.
  - Cards replay exactly, viewers never see evidence they can't read (not even as a count), and spot checks go to the named person. ([#1107](https://github.com/thetangstr/agentdash/pull/1107), @thetangstr)
- **Performance manager.** A designated agent, the Chief of Staff by default, reads scorecards and proposes changes or recommendations. Only people decide, and a "pause" recommendation never pauses. ([#1107](https://github.com/thetangstr/agentdash/pull/1107), @thetangstr)
- **Start from a brief.** Paste a business brief, send it to the planner, and review its scenario plan. Draft a profile and request a hire; the profile is applied after approval. ([#1107](https://github.com/thetangstr/agentdash/pull/1107), @thetangstr)

## Fixes

- **Image builds pin Node 24.** The floating `lts` base image had moved to a Node release without corepack, which broke every image build. ([#1107](https://github.com/thetangstr/agentdash/pull/1107), [#1108](https://github.com/thetangstr/agentdash/pull/1108), @thetangstr)
- **Operators:** `scripts/hosted/internal-box.mjs` creates, claims and fills an internal box in one resumable sequence that an agent can run (`doc/runbooks/internal-box.md`). ([#1110](https://github.com/thetangstr/agentdash/pull/1110), @thetangstr)

## Upgrade Guide

Back up before applying. Migrations run at startup.

- **`0153_microsoft_account_oid_backfill`: Better Auth 1.7 keys Microsoft accounts by `oid` instead of `sub`.**
  - The migration re-keys each `account` row with `provider_id = 'microsoft'` from its stored id token. The token's `sub` must equal the row's key, and the new key is the token's `oid`. Google and password rows are untouched, and re-running it changes nothing.
  - The startup log reports `agentdash: migration 0153 …` with counts, and names (by `account.id`) any row it left unchanged: a row with no usable stored token, or one whose oid another row already holds. Better Auth 1.7 also refuses sign-in on any key shared by two rows, so those are named too. Fix a named row before Microsoft users rely on it, or that user signs in by email instead.
  - Rolling back below this release needs the reverse (`account_id` back to the stored token's `sub`), or Microsoft sign-in fails on the old version.
- **`0154`–`0156` are additive:**
  - agent profiles, revisions and application receipts;
  - issue responsibility mapping;
  - `companies.agent_access_enforcement` (default `off`) and `companies.performance_manager_agent_id`;
  - `evaluation_events.access_class` (default `company`) and `subject_agent_id`;
  - `routine_run_occurrences`.

  Nothing is dropped or rewritten.
- **Access enforcement stays `off`** for every company until an admin changes it in Company settings. Try `shadow` first: it shows what your rules would refuse before anything is refused.
