# v2026.1010.0

> Released: 2026-10-10.

Work assigned to a person now goes to the agent that person stewards. The agent takes the first pass, writes up its recommendation and asks its person before completing, and the person can answer from their own Claude or Codex session through the bridge, with an email pointer when something is waiting on them. This update also adds the gpt-6 Codex models, restores the My agent link to the sidebar, tightens document connections to the steward's own sign-in, keeps document text out of stored runs, honors HTTP adapter deadlines set in seconds, and opens hosted invitations while keeping the public waitlist.

## Breaking Changes

- **Assigning a person assigns their agent.** Any assignment of a person who stewards an active agent, by a person or an agent, goes to that agent and wakes it; the response and activity log record `routedToStewardedAgent`. It stays with the person when `assignToPerson: true` is sent, when the person assigns themselves, when the agent is the caller, when the person is a review or approval participant, or when the agent is paused, terminated, pending approval, in error or failed its harness preflight. An agent may hand its own issue to its own steward without `tasks:assign`. ([#1087](https://github.com/thetangstr/agentdash/pull/1087), [#1092](https://github.com/thetangstr/agentdash/pull/1092), @thetangstr)
- **Document connections come only from the steward's own sign-in.** For document providers (`microsoft`, `sharepoint`), an agent resolves only its current steward's private connection. Workspace-visible and agent-owned document connections are refused at creation and never resolved, and the generic connection-create route refuses document providers. Each owner may hold one active `microsoft` connection. ([#1086](https://github.com/thetangstr/agentdash/pull/1086), @thetangstr)
- **Rejecting an approval wakes the requesting agent.** Approval decisions from every surface now wake the requester on reject as well as approve. ([#1093](https://github.com/thetangstr/agentdash/pull/1093), @thetangstr)

## Highlights

- **First pass, then ask.** A new managed mandate block, `steward-first-pass`, tells an agent to restate work that came via its steward, recommend an answer, and ask with `ask_user_questions` before completing unless its mandate allows otherwise. The wake carries `routedFromStewardUserId`. ([#1092](https://github.com/thetangstr/agentdash/pull/1092), [#1093](https://github.com/thetangstr/agentdash/pull/1093), @thetangstr)
- **Answer from your own session.** Questions an agent addresses to a person appear in that person's bridge inbox, and `POST /api/bridge/inbox/answer` (person endpoint token with `bridge:inbox`) answers them; the answer wakes the agent. `agentdash-connect` 0.4.0 adds the `inbox_answer` tool. ([#1093](https://github.com/thetangstr/agentdash/pull/1093), @thetangstr)
- **Email when something waits on you.** A pointer email (agent, issue identifier, link; no agent-written text) when a question or approval newly waits on a person, at most one every 15 minutes, with an opt-out on My agent. Instances without email configured send nothing. ([#1093](https://github.com/thetangstr/agentdash/pull/1093), @thetangstr)
- **gpt-6 Codex models.** The Codex model picker lists gpt-6.1-sol, gpt-6-astra, gpt-6-sol and gpt-6-luna, all with fast mode. They need Codex CLI 0.160 or later. The default model is unchanged. ([#1084](https://github.com/thetangstr/agentdash/pull/1084), @thetangstr)
- **My agent in the sidebar.** My agent is the first row under Team again; the account-menu entry stays. The Team toggle reads Show team or Hide team. ([#1083](https://github.com/thetangstr/agentdash/pull/1083), @thetangstr)

## Improvements

- **Waiting on you shows your agents' stopped work.** Home, Decisions and the badge list blocked issues on agents a person stewards, using the same definition as the bridge inbox, excluding dependency-blocked and recovery issues. ([#1092](https://github.com/thetangstr/agentdash/pull/1092), @thetangstr)
- **Routing notice.** Wherever an assignee changes, the UI says when the issue went to a person's agent. ([#1092](https://github.com/thetangstr/agentdash/pull/1092), @thetangstr)
- **Document text stays out of stored runs.** Document text framed by the server is withheld from run logs, run events and results; with document access on, a run's log is readable only by the agent, its steward and instance admins, and stored output expires after 30 days. Document access itself is not enabled in this release. ([#1089](https://github.com/thetangstr/agentdash/pull/1089), @thetangstr)
- **Accurate tool contracts.** MCP tools advertise wrapper descriptions and numeric bounds as validated, and steward clients are directed to `agentdashGetMyMandate`. ([#1082](https://github.com/thetangstr/agentdash/pull/1082), @thetangstr)
- **Hosted invitations.** Hosted signup can admit invited customers through single-use invitations while the public waitlist stays in place. ([#1088](https://github.com/thetangstr/agentdash/pull/1088), @thetangstr)
- **Document access plan.** The per-steward Microsoft 365 document access plan is published. ([#1085](https://github.com/thetangstr/agentdash/pull/1085), @thetangstr)
- **Release verification.** Stable verification is shorter without dropping coverage, and stable decisions stay tied to reviewed source. ([#1079](https://github.com/thetangstr/agentdash/pull/1079), [#1080](https://github.com/thetangstr/agentdash/pull/1080), @thetangstr)

## Fixes

- **HTTP adapter deadlines in seconds.** A finite `timeoutSec` is honored before `timeoutMs`, converted to milliseconds and capped at the timer maximum. ([#1081](https://github.com/thetangstr/agentdash/pull/1081), @thetangstr)
- **Approvals show their issue.** Approval lines in the bridge inbox name the linked issue. ([#1093](https://github.com/thetangstr/agentdash/pull/1093), @thetangstr)

## Upgrade Guide

- Two database migrations: `0147_document_connection_owner_uq` (unique active `microsoft` connection per owner; refuses to apply while any owner holds two, so revoke extras first) and `0148_steward_email_notices` (email notice rows and notification preferences; additive). Apply with migrations allowed.
- Agents that should keep a human-only decision with a person must send `assignToPerson: true`. Existing agents receive the new mandate block through the managed instruction refresh before their next run; `HEARTBEAT.md` changes apply to new agents only.
- People using the bridge should rerun the connect command to get `agentdash-connect` 0.4.0 and `inbox_answer`.
- Email notifications start on deploy where email is configured; each person can turn them off on My agent.
- Move a Codex agent to a gpt-6 model only after the host's `codex` CLI is 0.160 or later.
