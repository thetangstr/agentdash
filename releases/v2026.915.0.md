# v2026.915.0

> Released: 2026-09-15.

One squash past v2026.914.0. No migration; the journal tip is unchanged, so
applying this is a symlink swap and a restart. Server behaviour changes, so a
UI-bundle swap cannot pick it up. **Pairs with `agentdash-connect@0.2.1`** —
the CLI half of the owner-identity features below; either half alone degrades
cleanly to 0.2.0 behaviour.

## Behaviour Changes

Everything here is a field finding from the first two stewards through the
0.2.0 connect flow, plus one identity incident on a shared machine.

**Every inbox response and every redemption now names its owner.** A machine
can hold the wrong person's inbox credential — on a shared machine, a
re-pairing under a different signed-in account replaced the token silently and
the inbox switched people with nothing on screen saying so; the reader had to
trace server source to learn whose approvals they held. The sync response and
the redeem response now carry the owner's display name and email, so every
render can open "AgentDash inbox — Chris Hong" and the CLI can refuse to
silently replace a different person's connection. Display identity only; no
credential, no authority.

**The connect page defaults to the address you are using.** Reversed from the
previous release on field evidence: the published-address default guaranteed a
dead command for the first remote steward, whose VPN cannot resolve the
published LAN name. Self-use is the page's own stated case; the forwarding
caution now lives on the published option's label. A steward whose two
addresses agree still sees no choice at all.

**The page's printed command pins `agentdash-connect@latest`.** A bare package
name lets npx serve a cached pre-0.2 CLI, which silently skips the inbox half
of the pairing.

**Delivered inbox text stops naming a tool the session cannot call.** The
closing line pointed at `inbox_decide`; deciding in-session is not wired yet,
and the first steward through said so. Both renderers now point at the
AgentDash page.

**Connected machines are visible and revocable on My Agent.** The list went
missing with the old connect page; a credential you cannot see is one you
cannot revoke, and a dead-but-enrolled endpoint sat unreachable for days to
prove it. The connect card also names the signed-in account before the button
— everything a code mints binds to that account, and a shared or wrong-session
browser is caught at the moment it matters.

## Known follow-up

Deciding from inside the session still requires the stdio bridge server, which
is not yet distributed to steward machines.
