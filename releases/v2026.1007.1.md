# v2026.1007.1

> Released: 2026-10-07.

Run-log reads now yield between lines so other requests can run while an unverified log is redacted. Chats and live transcripts follow the newest message until you scroll up. Agents can be set to wake only when a board member assigns them an issue, with a run-window audit route that shows exactly what woke them. No migrations. Everything merged since v2026.1007.0 (`9572ef844`).

## Added

- **Assignment-only wakes** (#1068). An agent can be set to start runs only when a board member assigns it an issue through a board API key (`runtimeConfig.wakePolicy: "board_assignment_only"`, set by board users only). Every other attempt to wake it, from a timer, a comment, a retry, a recovery sweep or another agent, is refused and recorded as a skipped wake with a stable reason code, and background recovery leaves its issues alone. Turning the setting on cancels queued runs that wouldn't qualify. See `doc/AGENT-WAKE-POLICY.md`.
- **Run-window audit** (#1068). `GET /api/agents/:id/run-window?from=&to=` lists every run, wake and comment for an agent within a window of up to 7 days, for board users who can manage agents, filtered by restricted-project visibility.
- **Instance identity on the health check** (#1068). `/api/health` reports `instanceId` (the real instance id, or a display label set with `AGENTDASH_INSTANCE_LABEL`), `dataDirName`, `signUpDisabled` and `trialAnonymousEnabled`.

## Fixed

- **Run-log reads let other requests through between lines** (#1069). Reading a run log redacted secrets in one blocking pass over the whole file; on the HQ instance a 624 KB log blocked every request for 25 to 35 seconds after a restart. Secret matching is now cached, and redaction yields between lines after a slice reaches its time budget; a single large line can still take longer. Unverified log data normally pages at 256,000 bytes with `nextOffset`, keeping a single oversized line intact; bytes already verified as redacted bypass that budget. A log written by the server is trusted as already redacted only within the same process and only while its secrets and redaction rules are unchanged. Nothing that was redacted before is served unredacted now.
- **Chats and live transcripts follow the newest message** (#1067). The issue chat, live run panes on the dashboard and the Ask chat now behave like the run page: they keep up with new messages while you're at the bottom, hold still the moment you scroll up, and resume when you click "Jump to latest" or send a message. Links to a specific comment are never overridden, and issues still open at their description.

## Upgrade notes

- **No migrations.** Rolling back to v2026.1007.0 needs no database restore.
- **Run log paging.** A log read may now return less than `limitBytes` with a `nextOffset`; clients that page on `nextOffset` (the UI does) need no change. Clients reading a whole log with one large `limitBytes` should page.
- **Wake policy codes are a stable contract**: `travel_pairing.wake_source`, `travel_pairing.not_issue_assignment`, `travel_pairing.not_board_key`, `travel_pairing.no_environment` and `travel_pairing.environment_mismatch`, with `payload.refusedReason` and `payload.requestedVia`. A run refused at start stays as a cancelled run that never executed.
