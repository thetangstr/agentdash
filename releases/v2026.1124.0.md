# v2026.1124.0

> Released: 2026-11-24.

## What's new

- **Codex cached input is counted once at the daily ceiling.** Codex input already includes its cached subset. Daily totals, the share spent on no-op runs, and newly recorded run token and complexity totals now count that subset once. Agents whose corrected daily usage is below their existing ceiling can take unattended work again.
- **Retired legacy intake no longer creates work.** New requests tagged with the retired origin are refused before creating issues or waking agents. Ordinary company tasks, including assigned tasks and children, continue to work; visible historical records remain readable.

## For admins

- Ceiling values, reset times and wake permissions are unchanged. This fix does not raise a ceiling or grant an override. Raw usage counters and monetary prices are unchanged.
- Historical Codex accounting uses the producing adapter recorded on the run, or retained invocation evidence scoped to the same company, run and agent. Missing or conflicting evidence keeps conservative additive counting; the current agent adapter, provider or model does not identify an old run.
- New runs retain their producing adapter when invocation events expire. Backfill uses a recorded adapter after an agent changes adapters; recorded usage is preserved and reported when the former source cannot be recovered.

## Upgrade

- No new database migrations or dependencies. When upgrading from an older release, apply any intervening migrations described in its release notes.
- Existing stored run token totals and mixed-adapter cumulative UI totals are not backfilled by this change. Daily ceiling totals can correct historical Codex runs when retained provenance identifies them; unknown history remains conservative.
- This release does not add company goal publication or change company assignments.

## Security

- Refused retired-origin requests create no issue, issue counter update, agent wake or run. Child creation rejects origin fields rather than silently turning a retired-origin request into ordinary work.
- Historical origin conflicts are returned only for records the caller can see in the same company. Hidden or foreign records are not disclosed. Existing permissions for ordinary tasks remain in force.
- Token aggregation excludes cost events belonging to another agent, and repeated invocation events cannot multiply the run total.

## Breaking Changes

- New top-level issue requests tagged with the retired legacy origin now return 410; a visible historical duplicate retains its 409 conflict response. The MCP issue-create tool also refuses new retired-origin requests. Historical list and lookup support, the stored origin value and its index are retained. Child-create validators reject `originKind` and `originId`.

## Fixes

- [#1150](https://github.com/thetangstr/agentdash/pull/1150): correct Codex accounting at the daily ceiling and for newly recorded run totals without reducing exclusive-input or unknown-adapter usage.
- [#1151](https://github.com/thetangstr/agentdash/pull/1151): retire legacy intake while preserving historical visibility and ordinary task assignment.
