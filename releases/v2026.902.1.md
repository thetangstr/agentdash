# v2026.902.1

> Released: 2026-09-02

Candidate commit `06f04b5a9` on `main`, nine squashes past v2026.902.0. One
migration, forward-only. Verified live on an internal instance before the cut:
every change below was exercised against a running server in a disposable
company, and the evidence is recorded on the AGE board.

## Behaviour Changes You Must Read First

**This release carries a migration, and there is no way back by code alone.**
`0123_funny_the_stranger` adds provenance columns to agent API keys and
backfills existing keys named `default` that were minted with their agent.
Drizzle has no down-migrations. Rolling this release back means restoring the
database backup taken before the update and losing whatever was written since.
The OTA updater refuses a migrating release unless run with
`--allow-migrations`; that refusal is correct, read it before overriding it.

**A Hermes run that lets Hermes decide for a human now fails.** Hermes's
built-in `clarify` tool is a terminal prompt. Nobody is at that terminal in a
headless run, so it can only time out, and Hermes's fallback told the agent to
"use your best judgement and proceed". Such a run used to report success. It
now ends `failed` with `errorCode: human_question_unanswered`, the run log says
why, and the agent is told in its prompt to raise an `ask_user_questions`
interaction instead. Expect some previously "successful" runs to start
failing; each one is a question a person never received.

**Existing agents' generated mandates get smaller on their next run.**
Integration guidance (SharePoint, Gmail, Slack, the MSP demo) is now opt-in
skills rather than pages of every agent's `AGENTS.md`, and the refresh service
withdraws generated blocks the source no longer carries instead of leaving them
in place forever. Human-authored prose outside the generated blocks is
untouched. One design-partner agent's mandate had reached 53 KB of verbatim
default; that is the case this fixes.

## Governance Reaches the Runtime (Hermes)

- **Steward directives are delivered.** Every first-party adapter already
  rendered `paperclipAgentDirectives` into its prompt; the external Hermes
  adapter never did, so directives persisted, reported as pushed, and never
  reached the agent. They now render into every Hermes run in a fixed order:
  mandate → directives → harness rules → task. Where a directive and the
  mandate disagree about *how* to work, the directive wins; it never outranks
  the harness rules that follow it and, as before, it cannot grant capability.
  A steward's `{{ … }}` braces survive the template pass.
- **A push says whether it will be seen.** `POST …/directives` now returns
  `delivery` (`adapterType`, `delivered`, `via`, `detail`) and a `warnings`
  entry when the agent's adapter cannot render directives — the `process`
  adapter, and unknown external adapters. "Pushed" is no longer mistaken for
  "applied". Writing `agent_directives` rows directly is documented as
  unsupported.
- **The human-question channel fails closed** (see above). Detection is
  anchored to Hermes's own fallback strings, never to ordinary prose about
  "deciding".
- **Lean mandates.** Generated blocks are opt-in and withdrawable (see above).

## Honest Surfaces

- **Bridge enrollment names the real command.** The page printed a binary that
  does not exist, and the bare npm name it implied belongs to a third party, so
  `npx` fetched a stranger's package that exited 0. The page now prints
  `paperclipai bridge run`, explains that the CLI ships with the server, and
  says how to keep the bridge open. A repo-wide test refuses either wrong
  spelling in code, docs, and prompt surfaces.
- **A wrong method on a known route answers 405.** With an `Allow` header
  listing what the route accepts, computed from the router itself. Unknown
  paths still answer 404.
- **Every agent API key records what minted it.** Agent creation, onboarding,
  a connect code, or a person at the keys panel — with the creating user or
  agent where there was one. The keys panel says so in words, and the
  agent-creation response marks its bundled key `autoCreated: true`.
- **The sandbox is documented as it is.** `doc/AGENT-SANDBOX.md` records the
  four-variable control surface, its `off` default, that codex-local's
  `dangerouslyBypass*` flags have no bearing on `hermes_local`, and the
  measured minimum confinement for a uv-managed Hermes (`~/.hermes` *and*
  `~/.local/share/uv/python` read-only, plus a synthetic `HOME`).

## Known Limitations, Stated Plainly

- **The OTA update button does not yet honour the server's `canApply`.** A
  release the updater will refuse can still be approved from the page; the
  updater refuses it later. Fix is small and tracked.
- **Deleting a company that used directives or the bridge fails** with a
  foreign-key error (`agent_directives`, `bridge_endpoints` are not cleared
  before their parents). Only mk-profile companies that used those features
  are affected.
- **Per-agent `adapterConfig.env` values do not reach a Hermes child
  correctly** (they arrive as the literal string `[object Object]`).
  Pre-existing; host environment variables are unaffected.
- The clarify fallback is refused after the run, not interrupted during it:
  the adapter exposes no child pid to the wrapper. Delivering the question to
  the steward's inbox and bridge is separate work.
- A confined `hermes_local` run completing a real model turn (AGE-33) has not
  been executed; exec and exit under confinement were.
- OTA signatures are still not verified; provenance means the tag is on `main`.

## Held Back On Purpose

Three CI-only changes are green and unmerged by decision: the upstream-digest
workflow repair, the Docker build-order fix, and the wake-gate test isolation.
None affects a running instance. The inbox read-state narrowing remains held
for the same reason as last release: it needs its own placement signal.

## Upgrade Guide

This is an in-place upgrade. Preserve the existing database, configuration,
storage, and agent data; do not reinstall or reimport the instance.

1. Back up the database first (`paperclipai db:backup`). This release cannot
   be rolled back without it.
2. Apply. On the OTA path, pass `--allow-migrations` deliberately; on the
   source path, let the normal startup migration apply `0123` (it completes in
   under a second on a typical instance).
3. Confirm `GET /api/health` reports `status: ok`, then the post-install
   checks: `POST /api/health` answers 405 with `Allow: GET, HEAD`; a new
   agent's creation response carries `apiKey.autoCreated: true`; the
   enrollment page shows `paperclipai bridge run`.
4. To roll back: move code back with the rollback wrapper, **then restore the
   pre-update backup**. Keys minted after the upgrade lose their provenance
   columns; nothing else is lost by the restore beyond what was written since.

Existing `default` keys minted within two minutes of their agent are attributed
to agent creation by the backfill; keys a person named `default` later stay
`manual`.
