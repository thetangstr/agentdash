# v2026.1109.0

> Released: 2026-11-09.

> **Withdrawn on 2026-11-09. Do not install this release.** It is superseded; its changes will ship in a later release. Nothing was deployed from it.

Company-level decisions now belong to a company's owners and admins: deleting, archiving, exporting or importing into the company, changing its settings and budget, turning on company data sharing, creating CEO or chief-of-staff agents, and managing secrets someone else created. Members keep doing their work as before. This release also adds Fred, a built-in guide for owners, and one new database table for it.

## What's new

- **Company decisions belong to owners and admins.** These now need a company owner or admin: deleting or archiving a company; changing its settings (name, branding, budget, "approve new agents first", "new tasks start as to-do", attachment size); raising the budget to resume a paused company; importing into it; and exporting it. Members who open Company Settings see the settings read-only, with the line "Only owners and admins can change company settings."
- **Only owners and admins create leading agents.** Creating, hiring, activating or approving an agent with the CEO or chief-of-staff role, moving an agent into or out of those roles (including by restoring an earlier configuration), and letting an agent create other agents now need an owner or admin, including from your own Claude and from approvals answered in chat apps. Creating a key or connect code for a CEO agent or an agent that can create agents, or becoming its steward, also needs an owner or admin. Agents may still propose such a hire; an owner or admin decides it. Members still create their own ordinary agents, and each member's own personal agent works as before.
- **Secrets: create yours, manage your own.** Members can still save new secrets, for example for their own agents. Rotating, renaming or deleting a secret needs an owner or admin, or the person who created it.
- **Invites need the invite permission.** The onboarding invite for up to 25 people now checks the same permission as the regular invite.
- **Fred, a built-in guide.** A Fred link now appears at the bottom of the sidebar. Fred helps understand your company, prepare agent setup, and follow useful work through to evidence and outcomes; your Chief of Staff and existing agents keep their roles. An owner or admin sets Fred up by choosing the agent runtime and a monthly model budget, then agrees a first job. Setup and saving that brief run no model and turn on no recurring checks. Fred starts work only when an owner or admin asks it to start discovery, and new access, hires and other guarded changes still need approval. Fred's model usage counts toward your normal limits and costs.
- **A public page on how agent performance is judged.** The AgentDash website has a new page explaining how agent performance is evaluated from released evidence.
- **Feedback sharing is an admin choice.** A member's feedback vote is still saved, but only an owner or admin can turn on sharing feedback with AgentDash for the whole company.

## For admins

- Nothing to turn on for the protections. Fred stays unset for every company until an owner or admin sets it up from the Fred page. If a member used to change settings, the budget, imports or exports for you, either do it yourself or make that person an admin.
- An agent whose destructive actions are set to Blocked can no longer request HubSpot writes or send Slack messages. Both are refused with the ceiling message, as on the bridge. Under Approval required, Slack messages still follow the connection's send setting; there is no Slack approval step yet.
- Feature-flag changes accept only the switch names AgentDash knows. An unknown name is refused, and the refusal lists the known names.

## Upgrade

- One database migration, `0158`: it adds a new, empty table for Fred and changes nothing that already exists. No configuration changes.
- A CEO or chief-of-staff hire that a member filed before this release now needs an owner or admin to approve it.
- Rolling back to the previous release restores the earlier behavior, including the gaps described under Security. The new table is not removed.

## Security

- Before this release, any active member of a company, not only an owner or admin, could delete or archive the company, change its settings and budget, import over its records, export it, and rotate or delete its secrets. A member's export could include restricted projects and their issues, and every agent's instructions.
- Before this release, a member could also get a CEO agent's key, by creating one or, with permission to manage agents, by minting a key for an existing one, and use it to export, import or rebrand the company. A member could also raise the budget by resolving a budget warning, and a member's feedback vote could turn on company-wide feedback sharing.
- No setting closes these on earlier versions. Upgrade to this release.

## Breaking Changes

- Members (not owners or admins) now get 403 from: `POST /api/companies/:companyId/archive`, `DELETE /api/companies/:companyId`, `PATCH /api/companies/:companyId`, `PATCH /api/companies/:companyId/branding`, `PATCH /api/companies/:companyId/budgets`, company-scope `POST /api/companies/:companyId/budgets/policies`, company-scope budget incident resolution with `raise_budget_and_resume`, `POST /api/companies/import` and `/import/preview` into an existing company, `POST /api/companies/:companyId/imports/preview` and `/imports/apply`, and `POST /api/companies/:companyId/export`, `/exports/preview` and `/exports`. CEO-agent access to branding, imports and exports is unchanged.
- Creating or hiring an agent with role `ceo` or `chief_of_staff`, changing an agent's role into or out of those roles (PATCH and config-revision rollback), granting `canCreateAgents`, and approving or overriding such a hire require a company owner or admin, on every route and channel. Agents may file such hire approvals.
- `POST /api/agents/:agentId/keys`, `POST /api/agents/:agentId/connect-codes`, and stewardship assign or transfer for an agent with role `ceo` or `canCreateAgents` require a company owner or admin.
- Company secret rotate, update and delete require a company owner or admin, or the secret's creator. Create is unchanged.
- The onboarding batch invite route requires `users:invite`.
- `POST /api/issues/:issueId/feedback-votes` with `allowSharing: true` from a member no longer enables company sharing; the response includes `sharingNotEnabled`.
- `PUT /api/companies/:companyId/feature-flags/:flagKey` returns 400 for an unknown flag key.
- New capability `company:manage` in `GET /api/me/capabilities`.
