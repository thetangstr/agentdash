# AgentDash — complete roadmap to a comprehensive product

**Written:** 2026-08-16. Supersedes the scope of `2026-08-16-launch-tomorrow.md`,
which assumed a launch on the 17th. **Launch slipped by decision** to build this
properly rather than half-finish an authz migration on a live client system.

**Method.** Everything marked *measured* was probed against the running system or
grepped from the tree today, and says what was checked. Everything marked
*judgement* is my opinion about what this kind of product needs and is worth
arguing with. Items nobody has raised before are marked **NEW**.

**Standing decisions folded in:** error sink is **local only** — no client data
leaves the Mac Mini. Roles collapse to **admin + member**, open visibility,
restriction per project. Launch slips for comprehensiveness.

---

## 0. Corrections first — things that already exist

I have been wrong often enough on this project that the roadmap starts by
deleting work. Each of these was measured today, and each would have been a
plausible-sounding line item in a generic hardening plan:

| assumed missing | actually present | evidence |
|---|---|---|
| Rate limiting | auth, billing, invite, trial and default API limiters, with `trust proxy` spoofing handled | `server/src/middleware/rate-limit.ts`, 15 call sites in `app.ts` |

**The pattern worth naming:** this product's gaps are almost never "the feature
doesn't exist". They are "the feature exists and is not wired to anything". That
is the shape of the observability finding below, and it was the shape of the
hermes sandbox finding before it.

## 1. Observability and silent failure

The theme you asked to add. The finding is sharper than "we need telemetry":

**The instrumentation is complete and the sink is absent.** `captureServerError`
opens with `if (!target) return;` and `getTelemetryClient()` returns `null`
unless configured. Neither `mkboard.env` nor `uat.env` contains a single
observability key *(measured)*. So every error is caught, formatted, enriched
with method/url/body — and dropped on the floor. That is worse than no
instrumentation, because reading the code suggests coverage that does not exist.

| # | item | size | notes |
|---|---|---|---|
| **O1** | **Local error sink.** Persist every 5xx and every unhandled rejection to a Postgres table with fingerprint, count, first/last seen. This is the decided design — nothing egresses. | 1d | measured: the capture path already builds the full payload; only the sink is missing |
| **O2** | **Error surface in the UI.** A page showing recent failures grouped by fingerprint. Without this O1 is a table nobody reads. | 1d | |
| **O3** | **Failure alerting.** Email on heartbeat run `failed`/`timed_out`, on unhandled rejection, and on backup failure. SMTP, since no channel exists at all *(measured: 0 connector rows, 0 SMTP keys)*. | 1d | this is D5 |
| **O4** | **Health endpoint that can fail.** `/api/health` currently reports `status: "ok"` with adapter and bootstrap state *(measured)*, but nothing about DB latency, disk headroom, backup freshness, or stuck runs. A health check that cannot go red is decoration. | 0.5d | **NEW** |
| **O5** | **Silent-failure audit.** Systematic sweep for `catch` blocks that swallow, `if (client)` guards that skip, and `?? fallback` that masks. Each becomes: propagate, or log deliberately with a comment saying why it is safe. | 1.5d | **NEW** — judgement, but it is the same class of bug as the `'completed'`/`'succeeded'` mismatch and the inert Sentry client |
| **O6** | **Heartbeat liveness watchdog.** Nothing currently notices a run that starts and never ends. `RUN_LIVENESS_STATES` exists; no reaper consumes it. | 0.5d | **NEW** |

## 2. Authority, access and row-level security

This is where the plan you called out was thin. RLS was in the decisions doc as
D2 option C and never made it into L1–L4.

**Important framing:** with **0 projects on mkboard** *(measured)*, missing RLS is
not an open hole — it is a missing capability. Open visibility is the model you
chose. The gap is that no exception can be made yet.

| # | item | size | notes |
|---|---|---|---|
| **A1** | **Direction lock.** Drop `operator` from `canSetCompanyDirection`. Sam and Megan are `operator` right now and can edit Titus's goals. | 1h | was L1 |
| **A2** | **Role collapse to admin + member.** `owner`→`admin`, everything else→`member`. Includes fixing `normalizeHumanRole("member") → operator`, which today silently produces someone who can rewrite goals. Needs a data migration on both instances. | 1d | your D2 decision |
| **A3** | **`createdByUserId` on projects.** Makes "Sam's project" a real thing. Prerequisite for ownership-based editing and for A4. | 0.5d | D3 |
| **A4** | **Ownership-based editing.** You change what you created; admin changes anything. | 1d | D2 |
| **A5** | **RLS — hybrid.** Restriction flag per project, enforced app-side via one shared visibility predicate, with a Postgres RLS backstop on the two tables that carry `projectId` directly (`issues`, `cost_events`). Measured blast radius: **8 read paths in `projects.ts`, 20 in `issues.ts`** filter on `companyId` alone; `goals`, `issue_comments`, `heartbeat_runs`, `activity_log` need joins. **No Postgres RLS is used anywhere today.** | 2.5d | the thing missing from L1–L4 |
| **A6** | **Project name collision guard.** Unique `(company_id, lower(name))` plus a near-miss warning on create. | 0.5d | D3 |
| **A7** | **Email-bound invites.** Today an invite is a bearer link — whoever opens it takes the role. Mitigated by `autoApprove: false` on both colleague invites, but the approval names whoever clicked, not who you meant. | 0.5d | D1 |
| **A8** | **`operator`/member gets `agents:create`.** The role that can start projects cannot hire. Moot if A2 lands first — fold in. | 1h | |
| **A9** | **Audit coverage gap.** 247 `logActivity` sites but only **20 of 75 route files** *(measured)*. Nobody has checked whether the unlogged 55 contain anything that matters. Not necessarily a gap — needs an audit to find out. | 0.5d audit | **NEW** |

## 3. Continuity and operations

| # | item | size | notes |
|---|---|---|---|
| **C1** | **LaunchDaemons.** Five services are LaunchAgents in `~/Library/LaunchAgents` *(measured)*, so a power cut leaves the box dark until someone logs in. Move to `/Library/LaunchDaemons` with `UserName` set. | 1h, needs sudo | D6, was L2 |
| **C2** | **Restore drill.** Backups run and have never been restored. Fifteen minutes converts a hypothesis into a fact. | 15m | D7, previously skipped |
| **C3** | **Backups are on the same disk as the database.** *(measured:* `~/.paperclip/backups/`, same volume as the Postgres data dir*)*. One disk failure loses the data and every backup of it. Needs an offsite or at minimum off-volume copy. | 0.5d | **NEW** — the most consequential item in this section |
| **C4** | **Backups are unencrypted.** Plain `.sql.gz` containing all client data, on a box in a client office. | 0.5d | **NEW** |
| **C5** | **Server logs grow unbounded.** No `newsyslog` entry and no rotation in any plist *(measured)*; `postgres.log` is already 3.6 MB. Disk is 4% used so this is slow, not urgent — but it is the classic unattended-box failure. | 0.5d | **NEW** |
| **C6** | **Plaintext HTTP.** `PAPERCLIP_AUTH_PUBLIC_BASE_URL=http://mkmini.local:3102` *(measured)*. Session tokens and all client data cross the office LAN in the clear. Anyone on that wifi can read them. | 1d | **NEW** — judgement on urgency, fact on exposure |
| **C7** | **Database growth policy.** No retention for `activity_log`, `heartbeat_runs`, `workflow_events`, or run transcripts — the tables that grow per-run forever. Plugin logs have retention; nothing else does *(measured)*. Current DB size unmeasured (`psql` unavailable on this box). | 1d | **NEW** |
| **C8** | **Runbook.** What Titus does when it is broken and I am not there: how to restart, where logs are, how to restore, who to call. | 0.5d | **NEW** |

## 5. Agent-specific risk — the part that is peculiar to this product

Everything above applies to any server. This section is what makes AgentDash
different: autonomous workers acting unattended, overnight, in a client's
office, with credentials. **Judgement throughout** — none of this is a measured
defect, and all of it is the nature of the thing.

| # | item | size | notes |
|---|---|---|---|
| **G1** | **Prompt injection through work content.** Agents read issues, comments and transcripts. Anyone who can file an issue can write text an agent will treat as instruction. With connectors live this becomes "anyone who can file an issue can send mail as the company". | 2d | **NEW** — the highest-severity item on this page, and the least visible |
| **G2** | **Connector blast radius.** 0 connectors configured *(measured)*, so agents currently cannot reach anything. The moment one is added, the question "what can an agent do without a human" changes shape. Needs per-connector scopes and an explicit answer before the first one is wired. | 1d | **NEW** |
| **G3** | ~~The approval path has never run~~ **DONE 2026-08-16: exercised on uat and it works.** create→201/pending, approve→200 with decider recorded, re-decide→422 refused with the DB unchanged, reject→200 with note, all read back from the database; audit rows written for every step. Bonus findings: board mutations carry a CSRF origin guard, and MK-profile decisions require `revision` + `idempotencyKey` — optimistic concurrency was already built in. | done | **NEW** |
| **G4** | **Stewardship.** 5 of 6 agents have no steward *(measured)*. Stewardship is what makes an agent answerable to a person; Gate 3 assumes it. | 1h | D4 |
| **G5** | **Mandate expiry.** `mandates` carry `expiresAt` *(measured)*. Nothing was found that acts on expiry — an agent may be running on authority that lapsed. Needs verification, then enforcement. | 0.5d | **NEW** |
| **G6** | **Agent sandbox for hermes.** Proven for the `process` adapter; **not** for hermes, which all six live agents use. Root cause is packaging: our packages export raw `.ts`, so vendored hermes resolves the published `adapter-utils` with no sandbox code. | 0.5d, high risk | D9, was L4 |
| **G7** | **Agent output review.** Nothing distinguishes "the agent said it did this" from "this happened". For a product whose value proposition is delegated work, verification of agent claims is arguably the core feature, not a hardening item. | 2d+ | **NEW** — judgement, and the one I would most want to discuss |
| **G8** | **Transcript retention and client data.** Run transcripts contain whatever the agent read, retained forever, unencrypted, in backups that are also unencrypted. Compounds C4 and C7. | 0.5d | **NEW** |

## 7. Sequencing

Ordered by risk reduced per day, not by theme.

**Phase 1 — before anyone signs in (~3 days)**
A1 direction lock · A2 role collapse · C1 LaunchDaemons · C2 restore drill ·
C3 backups off-volume · M2 budget policy · G4 stewards · O1+O3 error sink and
alerting

*Rationale: every item is either cheap or protects against losing data. A1 and
A2 are the ones that change what Sam and Megan can do on day one.*

**Phase 2 — the capability you asked for (~4 days)**
A3 project ownership · A4 ownership-based editing · A5 hybrid RLS · A6 collision
guard · O2 error surface · O4 real health endpoint

*Rationale: RLS is the headline, but it is only meaningful once ownership exists,
so A3/A4 come first.*

**Phase 3 — make the agents safe to leave alone (~4 days)**
G6 hermes sandbox · G1 prompt injection · G2 connector scopes · G3 exercise
approvals · G5 mandate expiry · M4 runaway protection · O5 silent-failure audit ·
O6 liveness watchdog

*Rationale: this is the phase that earns "unattended". G6 first because it is
high-risk and everything else is easier to trust once it lands.*

**Phase 4 — durability (~3 days)**
C4 encrypted backups · C5 log rotation · C6 TLS · C7 retention policy ·
C8 runbook · M1 token metering · A9 audit coverage · M5 cost attribution

**Deferred pending discussion:** G7 agent output review, A7 email-bound invites,
G8 transcript retention.

**U1 — track upstream paperclip (added 2026-08-16 on the owner's direction).**
Measured: upstream `@paperclipai/adapter-utils` latest is 2026.722.0 with
canaries stamped *today*; it ships `dist/` + types (solving the raw-`.ts`
problem upstream) and a proxy-based, Linux-flavored sandbox — **no Seatbelt,
and none of the five sandbox symbols our patched hermes imports**. So upstream
cannot replace G6 tonight; instead G6 builds our dist with upstream's exact
exports shape so the fork stays convergent. The remaining work — rebasing our
0.3.1-fork line onto upstream 2026.x and carrying Seatbelt as a small delta
(or upstreaming it) — is real, grows with every upstream release, and wants
its own sitting.

**Total: roughly 14 working days** to the comprehensive product, versus the
1 night the previous plan had. That is the real cost of the word.
