# v2026.1102.1

> Released: 2026-11-02.

Agent scorecards now fill in on every install without extra setup, including for work an agent did before the upgrade. A hire drafted from a brief works for every agent runtime, the profile and approval screens show names instead of raw ids, and an agent setting up a hosted box can choose the model its agents run on. One migration, `0157`, adds indexes only.

## Highlights

- **Scorecards fill in by default.**
  - The evaluation feed that fills agent scorecards now runs unless `AGENTDASH_EVALUATION_INGEST_ENABLED=false`. Before, it ran only when that variable was `true`, which no install set, so a card could show 0 runs for an agent with real work.
  - The first pass reads each company's past records in bounded steps, so an existing install gets scorecards for work already done. A larger history continues at the next interval.
  - Each step is one short transaction, and the pass pauses between steps so other writers get in.
  - A company whose read fails waits before it is tried again (5 minutes, doubling to an hour) while the other companies carry on.
  ([#1119](https://github.com/thetangstr/agentdash/pull/1119), @thetangstr)

## Improvements

- **Hires from a brief work for every runtime.** A hire from a brief may now carry the runtime settings a process-based agent needs: command, arguments and working folder. They are checked the same way as a direct hire, and only the instance admin may set a host command. The draft profile never chooses the binary a new agent runs. ([#1119](https://github.com/thetangstr/agentdash/pull/1119), @thetangstr)
- **Profile, Activity and approval screens read right.**
  - Profile badges match what each field shows.
  - Activity rows name and link the agent.
  - Project, agent and person names replace raw ids in the access list, Reports to, revision history and the approval diff.
  - Approvals keep a short id next to each name, for example "Finance (aaaaaaa1)", so approvers can tell same-named projects apart.
  ([#1119](https://github.com/thetangstr/agentdash/pull/1119), @thetangstr)
- **A setup agent can set a hosted box's agent model.**
  - `agentdash_setup_status` reports `agentModel` (`required`, `configured`, `canConfigure`, `provider`, `model`, `options`), with no key material.
  - `agentdash_setup_adapter` accepts `preset: "hermes"` with a `provider` from the box's own list, a key and an optional model. The key is never echoed.
  - Self-hosted installs keep the existing adapter step.
  ([#1116](https://github.com/thetangstr/agentdash/pull/1116), @thetangstr)

## Fixes

- **A hosted box leaves placeholder mode once its model is set.** Setting a real provider on a hosted box turns off `PAPERCLIP_E2E_SKIP_LLM` in the process and the env file, so agents call the real model. The activity entry records it. ([#1116](https://github.com/thetangstr/agentdash/pull/1116), @thetangstr)
- **Hosted boxes refuse Token Plan keys.** A hosted box refuses an Alibaba Qwen Token Plan key (`sk-sp-`) with a plain reason (`provider_plan_key_not_allowed`), because those keys are licensed for interactive coding tools only. Self-hosted installs are unchanged. ([#1116](https://github.com/thetangstr/agentdash/pull/1116), @thetangstr)
- **The release log links every published release**, and v2026.1031.0's note on allowlisted advisories now says what is still allowlisted and why. ([#1117](https://github.com/thetangstr/agentdash/pull/1117), @thetangstr)

## Upgrade Guide

Back up before applying. Migrations run at startup.

- **`0157_evaluation_ingest_keyset_indexes`** adds four indexes:
  - `(company_id, updated_at, id)` on `heartbeat_runs` and `issues`;
  - `(company_id, created_at, id)` on `cost_events` and `issue_comments`.
  
  Nothing is dropped or rewritten, and an older release runs with the extra indexes, so a code rollback stays safe. On a very large install, writes to those tables wait while each index builds.
- **The scorecard feed starts by itself.**
  - It runs every 5 minutes, and the first pass starts up to one interval after startup.
  - Expect extra database reads while it catches up on a long history.
  - To keep it off, set `AGENTDASH_EVALUATION_INGEST_ENABLED=false` before upgrading.
- **Upgrading from before v2026.1031.0:** also follow that release's upgrade guide. It covers migrations `0153`–`0156`, and `0153` re-keys Microsoft sign-in accounts: rolling back below v2026.1031.0 needs the reverse.
- **Known limits:**
  - The feed's retry wait resets when the server restarts.
  - An `opencode_local` hire from a brief still needs its model passed through the API.
