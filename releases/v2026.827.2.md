# v2026.827.2

> Released: 2026-08-27

## Critical OTA Correction

- **Native readiness now checks the installed deployment** — The generated source-checkout wrapper validates the configured launchd label, pinned source SHA, authenticated health response, protected runtime env, database connectivity, and listening port directly. It no longer delegates upgrade success to a version-dependent MSP launch checklist from the target checkout.
- **Readiness evidence no longer exposes database credentials** — The source-checkout gate reports only that `DATABASE_URL` is configured and that PostgreSQL responds; it never prints the credential-bearing URL.
- **Failed first upgrades remain recoverable** — The updater writes mode-600 pending rollback state before checkout mutation. The canonical rollback wrapper consumes either the last successful deployment state or that pending state, so a readiness failure before the first success receipt still has a deterministic previous SHA.
- **`v2026.827.1` is superseded for native installation** — Its public provenance is correct, but an isolated native rehearsal showed that its post-restart readiness delegated to MSP/Hermes/partner-network defaults instead of the configured staging deployment and exposed a synthetic staging database URL. Native operators must use the checksummed `v2026.827.2` control asset instead.

## Application Payload

The application payload remains exact source `f552df77417143fd6a949eff8553b98578317f5e`. It includes resumable invited-user onboarding, truthful shared open-task counts, run-attributed issue comments, aggregate recovery limits, configured cost visibility, and bounded idle polling. This patch changes only reviewed release-control logic, rollback metadata, and regression coverage.

## Upgrade Guide

This remains an in-place source-checkout upgrade. Preserve the existing database, configuration, storage, and agent data; do not reinstall or reimport the instance.

Download these assets from this GitHub Release:

- `agentdash-mac-mini-source-launchd-v2026.827.2.mjs`
- `agentdash-mac-mini-source-launchd-v2026.827.2.mjs.sha256`
- `agentdash-release-control-v2026.827.2.json`

Verify the updater checksum and confirm that the manifest records source SHA `f552df77417143fd6a949eff8553b98578317f5e`. Run the downloaded control script without `--write` first. Refresh the wrappers while the currently installed SHA remains pinned, validate every generated shell with the macOS system Bash, then invoke `agentdash-source-update.sh` with the exact target SHA. Require readiness to pass and a mode-600 deployment receipt to exist. A healthy HTTP response without a successful wrapper exit and receipt is not an accepted upgrade.

Before upgrading, back up the database and run this read-only duplicate preflight:

```sql
SELECT company_id, created_by_user_id, COUNT(*)
FROM onboarding_sessions
GROUP BY company_id, created_by_user_id
HAVING COUNT(*) > 1;
```

Stop if the query returns any row. Otherwise, allow the normal startup migration path to apply only pending migrations. On any post-checkout failure, invoke the generated rollback wrapper; it will use pending state when no prior success receipt exists. Do not run ad hoc `git pull`, replace the installation, or restore a database backup without explicit operator approval.
