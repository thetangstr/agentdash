# Governed lead acknowledgment for Ross

Objective: make the lead's actual model decision a durable, source-backed commitment after the genuine lead-report/Ross-response exchange. Acceptance or challenge is not completion.

The pilot operator selects one same-project Ross recommendation and a stable commitment ID in an explicit private lead binding. The lead freshly reads the actual advice and returns a strict six-field JSON decision: accepted/challenged, title, rationale, checkpoint and future checkpoint time within 48 hours. Source text remains evidence, never permission. The lead has the existing two read tools; the model receives no arbitrary write capability.

The runtime authenticates the actual lead/run/checkout and designated-project role, checks the referenced Ross actor, succeeded run, scoped parent and exact advice comment, and loads a valid lead-authored commitment document. Only a sanitized 404 permits an empty baseline on a new assigned acknowledgment task; denied/failed reads do not. It rejects an existing commitment ID before writing. A private exclusive intent reserves the run before either mutation. The runtime posts the exact model acknowledgment, verifies API lead/run attribution, stores its source receipt, rechecks current/source authority, and appends one record with a version-checked PUT and exact readback. A first document uses baseRevisionId:null and must read back as revision1. Prior records are preserved. Reported delivery stays null; outcome verification stays not-performed.

There are two governed writes, not an atomic transaction. A posted acknowledgment may survive a later CAS or readback failure. Private intent/source receipts expose that partial result; the runtime never retries an ambiguous write. The normal heartbeat result is a qualified receipt linking the exact acknowledgment rather than a duplicate model comment. The ordinary lead-report path is unchanged.

Validation: seven acknowledgment regressions cover preservation, first-document creation, non-404 denial, attribution, malformed/foreign input, past/excessive checkpoints, duplicate run/commitment, source edits, multiline/literal-backslash semantics and ambiguous write/refused CAS/changed readback.
