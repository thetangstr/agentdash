# v2026.1002.1

> Released: 2026-10-02.

The Chief of Staff (CoS) chat no longer goes quiet, the CoS can turn a chat request into a task, and finished work now needs your Accept. Also a phone redesign, a founder-stays-owner fix, security fixes and backup fixes. One migration (`0143`). Everything merged since v2026.1002.0 (`f0aba163b`).

## Changed

- **The CoS chat never goes silent** (#981). On a hosted box every reply had started failing with Z.AI "Insufficient balance" (HTTP 429, code 1113). Z.AI bills its pay-as-you-go API and its GLM Coding Plan on separate addresses, and Hermes kept using whichever one it first reached. AgentDash now pins the Coding Plan address first, and falls back to the other only if the first does not answer. If a reply still cannot be made, the chat shows "CoS couldn't reply" with the reason and a Retry button, instead of sitting on your message forever. Replies now arrive live, without a refresh, and "CoS is thinking..." shows while you wait. Only the person who wrote a message can retry it.
- **The CoS creates tasks from chat** (#973). Ask the CoS for work and it can suggest a task as a "Create this task?" card with a title, a description and who it goes to. Nothing is created until the person who asked clicks Confirm ("Not now" dismisses it). In a shared chat, someone else saying "ok thanks" never confirms it for you. You can only hand work to agents you can see, and the CoS makes at most five suggestions every ten minutes.
- **A review loop for finished work** (#976). When an agent's deliverable is waiting for review, the Result block on the issue shows Accept and Request changes. Accept moves the issue to done and marks the deliverable accepted. Request changes asks for a note (up to 2,000 characters), posts it as a comment, and sends the work back to the agent. Only people can accept: agents can no longer mark their own work approved or merged.
- **Shipped means accepted** (#976). Shipped, Home and the cost totals count only work a person accepted. An agent closing its own issue no longer ships its work. Local file paths are never shown or linked; the row says "The agent saved this on its computer. Ask it to attach the content." The Shipped and Home empty states now explain this.
- **Plain language in the CoS and onboarding** (#973, #974). The plan card shows roles as "Proposal Drafter", not `proposal_drafter`, hides fields that are Unknown, and no longer shows the adapter name. The CoS prompts ask for plain wording. The wizard opens on the right step when you already have a company, never offers to create a second one by accident, and says "Add an agent". A signed-in person with one company lands in its CoS chat. First-run steps are marked optional with a "Skip for now". New Agent is "Hire a new agent", with the technical settings under Advanced. Raw system events are hidden from Home and Activity unless you ask for them.
- **A phone layout for the whole app** (#965, #966, #967, #982). Team, Org chart, Work, Shipped, Home, Decisions, issue detail and Ask have phone layouts, with an overflow menu, scrollable tabs and docked composers. On phones, text is at least 12px, buttons and links are at least 44px to tap, bottom-nav labels read, toasts no longer cover the nav, and the connection dot and Report button sit in the header. The plan card fits a phone. A new test checks ten pages at 390px for overflow and tap size.
- **Quieter, consistent numbers** (#979). The trial banner and billing page share one billing request instead of repeating it, so you no longer hit rate limits just by keeping the app open. The app stops asking about features that are switched off, which removes a flood of 404s in the console. Token figures read the same on every page.

## Fixed

- **A founder stays the owner** (#975). Hiring agents during onboarding could quietly demote the founder from owner to member. It no longer rewrites an existing role. Hired agents keep their proposed role (never CEO or Chief of Staff), the person who confirms a plan becomes the accountable decider for those agents, and each agent's title now shows before its role.
- **Backups keep the whole database** (#972). Backup and restore now handle column defaults that call functions defined later, custom domains and composite types, exact timestamp and interval precision, and generated columns, so a restored copy matches the original.
- **Links use the public address from the config file** (#964). Invites, emails and billing links use `auth.publicBaseUrl` from the config file when no environment variable is set.

## Security

- **Signing out ends live updates** (#968). A signed-out or removed person stops receiving live events at once, and changes to who can see an agent apply on the next event rather than the next heartbeat.
- **Budget activity respects project visibility** (#970). Budget alerts, approvals and activity for a restricted project no longer show to people who cannot see that project, in the feed, badges, digest and live events.
- **Member emails and invite details stay private** (#970). Agent grants no longer expose member emails in members, invites and join-request responses, and invite responses never include the token hash or the invited email.

## Internal

- **Per-company sandbox spike** (#969). A prototype image and lifecycle API for running a company's agents in an isolated sandbox, with a separate signer and a per-identity network allow-list. Nothing ships or runs in a release from this yet, and it is not used by any current feature.

## Upgrade notes

- Migration `0143_message_author_user` adds one nullable column, `assistant_messages.author_user_id`. It runs on its own at boot. Messages from before it have no recorded author, so they cannot be retried from the error card; the person sends them again.
- Existing Z.AI installs fix themselves. On the next restart AgentDash picks the working Z.AI address from the stored key and pins it in every Hermes profile. A box with no stored key, or one not yet restarted, shows the error card with a hint to save the model key again in Settings.
- Founders who were already demoted by the old bug need the operator repair. It is not automatic. Run `agentdash doctor repair-founder-owner` to see companies with no active owner and the evidence for each member. It is a dry run until you add `--apply --company <id> --user <id>`, which promotes only that person.
- Agents can no longer approve their own work. A work product written by an agent or an assistant grant with status `approved` or `merged` is refused with 403 `work_product_self_acceptance`. Anything that did this should hand the work to a person to Accept.
- Shipped now counts accepted work only, with a cutoff of 2026-10-02. Work finished before that date on an issue that is done still counts as accepted, with no data change. From that date, work counts only when a person accepts it, or approves it directly.
