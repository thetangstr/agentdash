# v2026.1123.0

> Released: 2026-11-23.

The Codex model list in an agent's configuration now comes from the Codex CLI's own catalog, so OpenAI's newest models are selectable without waiting for an AgentDash release. gpt-6.2 Sol, gpt-6.2 Astra and gpt-6.1 Terra are listed. The inbox's agent list no longer shows terminated agents or hires awaiting approval. No migrations.

## What's new

- **Codex models follow the Codex CLI.**
  - The model list for a Codex (local) agent used to be a fixed list. Live lookup worked only with an OpenAI API key, so an install that signs Codex in with a ChatGPT account saw only that list, and each new OpenAI model waited for a release.
  - AgentDash now reads the catalog the Codex CLI keeps for its signed-in account, `models_cache.json`, which Codex refreshes from OpenAI on every run. Its models come first, in Codex's own order. Models Codex hides itself, such as its internal review model, are left out. The built-in list still follows.
  - The catalog is read from the shared Codex home and from each company's managed Codex home, but only where that home uses the shared sign-in. When the copies differ, the one written by the newest Codex version wins.
- **gpt-6.2 Sol, gpt-6.2 Astra and gpt-6.1 Terra** are in the built-in list, with Fast mode. The older gpt-6 entries are now labelled previous or legacy, matching Codex's own catalog.
- **The inbox lists only agents that can take work.** `POST /api/bridge/inbox/agents` (the `inbox_agents` tool in agentdash-connect) no longer returns `terminated` agents or hires still `pending_approval`. `POST /api/bridge/inbox/propose` no longer resolves a name to one of them. A rejected hire with the same name as a live agent no longer makes that name ambiguous. A name that matches only a dead agent now comes back as a question instead of a confirmation that would then fail. Paused agents are still listed, because work can still be assigned to them.

## For admins

- **Keep the Codex CLI current.** A model being listed does not mean your agents' Codex CLI can run it. Codex CLI 0.148.0 refused gpt-6.1 Sol with "The 'gpt-6.1-sol' model is not supported when using Codex with a ChatGPT account". gpt-6.2 Sol, gpt-6.2 Astra, gpt-6.1 Terra and gpt-5.6 Terra each ran on 0.171.0 under a ChatGPT sign-in.
  - Check the CLI your agents run: `codex --version`, on the PATH the AgentDash service uses.
  - Update it with `npm install -g @openai/codex@latest`.
- The model list shows what the newest Codex on the machine knows about. After updating Codex, the list catches up the next time any Codex run refreshes its catalog.
- A model you type in by hand still works as before.

## Upgrade

- No migrations. Upgrading from v2026.1111.0 or earlier also runs the migrations of the releases in between:
  - from v2026.1110.1 or earlier, `0162` from v2026.1111.0;
  - from v2026.1109.1 or earlier, also `0158` to `0161` from v2026.1110.0.
  Their notes describe each one.
- Rolling back to v2026.1111.1 brings back the fixed Codex model list and the old inbox agent list. Nothing stored changes.

## Security

- A company's managed Codex home counts toward the model list only while it uses the shared sign-in. A company whose Codex is signed in to a different account does not shape the list the other companies see. Only model names, descriptions and order are read from the catalog, never credentials.
- The inbox agent list still carries only each agent's id, name and role.

## Breaking Changes

- None for the published contract. `POST /api/bridge/inbox/agents` returns fewer agents. A client that looked up a terminated or pending agent by name through the inbox now gets no match.
